# Conformance: the test environment and the browser matrix (W6)

Rows for `docs/conformance.md`. Each claim names the specification, where the behaviour lives,
and the environment test or interop cell that proves it. The environment tests are in
`tests/testenv_*.rs` and run with `scripts/test-env/run.sh env`; the interop cells are in
`scripts/test-env/interop/*.spec.mjs` and run with `scripts/test-env/run.sh interop`, where
`interop/gate.mjs` checks the matrix (C3).

## Browser matrix (C3)

Every cell runs in Chromium, Firefox and WebKit (Playwright, headless). A cell is `pass` or a
cited `n/a`: **na-browser** (the browser lacks the feature, by its own capability API at run
time or a release note) or **na-env** (the headless build in the image lacks it: not tested).

## Not tested here

| What | Why |
|---|---|
| Safari | Playwright's WebKit is the Linux port with its own media and WebRTC stack; real Safari cannot run in a Linux container |
| H.264 with Firefox | Firefox does H.264 through Cisco's OpenH264 plugin, downloaded after install; the offline image never fetches it (na-env) |
| mDNS-hidden candidates with WebKit | WebKit's Linux ports publish their `.local` names through the Avahi daemon over the system D-Bus; the image runs neither, so nothing answers for WebKit's names (na-env) |
| TURN over TLS 1.3 | The image's coturn fails every TLS 1.3 handshake; the environment's client offers TLS 1.2 |
| macOS and Windows | The environment is Linux network namespaces |
