# Conformance: fuzzing and the repository's gates (stream W7)

Rows for `docs/conformance.md`. These claims are about the repository rather than the protocol:
what is fuzzed, and what CI refuses.

## Fuzzing

Every parser that takes bytes from a peer, a server or an untrusted file has a fuzz target, and
the state machines above the parsers have stateful targets. `fuzz.yml` runs them (pull requests:
the stateful targets for 60 s each; a dispatch with `targets: all`: every target, the stateful
ones for the whole duration and the parsers for at most 60 s), with debug assertions and overflow
checks; `oss-fuzz/build.sh` builds all of them. `scripts/check-fuzz-registry.py` fails when a
target is not in both.

## Gates

| Claim | Where | Checked by |
|---|---|---|
| No test is ignored, commented out, compiled by no `mod`, or behind a platform `cfg` without a listed reason and a covering test | `docs/test-exclusions.md` | `scripts/check-test-inventory.py` (`cargo.yml`, `test_inventory`) |
| Every test this document's fragments name exists | `docs/conformance/*.md` | `scripts/check-test-inventory.py` |
| Every upstream test has a fork test, a mapping or a reason | `docs/upstream-test-parity.md`, `docs/upstream-tests/` | `scripts/check-test-parity.py` |
| The workspace's tests run on macOS and Windows as well as Linux | `cargo.yml`: `test_platforms` | the job itself |
| Every action is pinned to a commit SHA; no workflow uses `pull_request_target`; no job that can run on a self-hosted runner admits a fork's pull request | `.github/workflows/*.yml` | `scripts/check-workflow-pins.py` |
| Every fuzz target is built by OSS-Fuzz and run by CI | `fuzz.yml`, `oss-fuzz/build.sh` | `scripts/check-fuzz-registry.py` |
