# RFC 8834: Media Transport and Use of RTP in WebRTC

Spec: RFC 8834, January 2021 (Standards Track). Audited against fork master 8916bc3.
Sections covered: 4 to 8, 10 to 13 (all normative text). Sections 1 to 3, 9, 14, 15 carry no
requirement on an endpoint. Where a clause delegates to another RFC, the clause-level detail is in
that RFC's file; the verdict here is the roll-up.

The engine is a transport: it does not encode, decode, capture or render. Clauses that can only be
met by an encoder or decoder are `n/a`; clauses the engine could meet by acting on RTP/RTCP (or by
handing the application what it needs) are judged against the engine.

## Gaps, in order of importance

1. **RTCP as a negotiated, scheduled protocol (L).** RFC8834-4.1-14 to -19, 4.6-2, 4.6-3, 10-6,
   4.5-2, 4.5-4. One scheduler for the session: interval from RTCP bandwidth (`b=RS`/`b=RR`/`b=AS`,
   5% default), member count, randomisation, reconsideration, participant timeout; compound versus
   reduced-size decided by the negotiated `a=rtcp-rsize`; reject or handle a peer without
   `a=rtcp-mux`; write `a=rtcp-mux-only` when the policy is `require`. This is the same work package
   as RFC 3550 6.2/6.3 and RFC 4585 3.5.
2. **CNAME (S).** RFC8834-4.9-2, -3, -4, 4.1-10. One RFC 7022 CNAME per peer connection (96 random
   bits, base64), written in every `a=ssrc ... cname:` line and in every SDES, receiver reports
   included; an option to share it across connections (4.9-5).
3. **SSRC collisions (M).** RFC8834-4.1-6, 4.8-5, 4.8-6, 12.2.2-1. Detect a received SSRC (RTP or
   RTCP, or a remote `a=ssrc`) equal to a local one; BYE, choose a new SSRC, keep MID/RID, raise
   negotiation-needed so the new `a=ssrc` is signalled.
4. **Circuit breaker, RFC 8083 (M).** RFC8834-7.1-1, 7.2-2, 7.2-3. All four breakers, from data the
   report interceptors already have; the outcome is an event to the application (stop sending).
5. **Bandwidth limits (M).** RFC8834-7.1-3, 7.1-4, 5.1.6-1 to -3. Read `b=AS`/`b=TIAS`/`b=CT` into
   the sender (cap for pacer and estimator, exposed to the application), write them on request;
   TMMBR/TMMBN packet types, the sender honouring a TMMBR and answering TMMBN.
6. **Congestion control on by default (S, a decision).** RFC8834-7-1, 7.1-2, 6-1. The estimator
   and pacer exist; the default chain has neither.
7. **SDES MID item and the MID extension for audio (S).** RFC8834-4.1-13, 5.2.4-1. SDES item 15
   parsed and sent; MID registered for audio in the default set; optionally stamped on send.
8. **Mandatory header extensions in the default set (S).** RFC8834-5.2.2-1, 5.2.5-1: register
   ssrc-audio-level and CVO by default. RFC 6904 encryption (M) for RFC8834-5.2.2-2, or a recorded
   decision that Cryptex replaces it.
9. **Clock-rate and payload-type switches (M).** RFC8834-4.3-5, -6, -7 with RFC 7160: re-bind a
   remote stream when its payload type changes; jitter per RFC 7160 4.3.
10. **Unsignalled SSRCs by payload type (S).** RFC8834-4.8-3: the RFC 8843 9.2 payload-type step
    when a packet has no MID and several sections exist.
11. **Feedback the application never sees (S).** RFC8834-5.1.3-2, 5.1.4-1/-2, 5.2.1-1: deliver SLI;
    add RPSI; answer RTCP-SR-REQ with an SR; RFC 6051 header extensions.
12. **Unbundled sessions (XL, decision D2).** RFC8834-4.4-1.
13. **Robust compound parsing (S).** RFC8834-4.1-23: a malformed sub-packet should cost that
    packet, not the datagram's earlier valid ones.
14. **Leap seconds (S).** RFC8834-4.10-1, see `rfc7164.md`.

## Bugs found

1. **CNAME is the application's stream id, and differs per stream and from the receiver reports'.**
   `src/peer_connection/sdp/mod.rs:1241-1259`, `src/peer_connection/handler/interceptor.rs:261-272`.
   Reproduce: add an audio track with stream id `a` and a video track with stream id `b`, create an
   offer and drive both senders plus one receiver for two seconds; assert that every `a=ssrc ...
   cname:` value and every SDES CNAME written by `poll_write` is the same string, and that it is not
   `a` or `b`. Today there are three values.
2. **Reduced-size RTCP is sent without being negotiated.**
   `src/peer_connection/sdp/mod.rs:942` writes `a=rtcp-rsize` unconditionally and nothing reads the
   remote's. Reproduce: set a remote offer whose video section has `a=rtcp-fb:96 nack` and no
   `a=rtcp-rsize`, feed RTP with a sequence gap, and assert the NACK that `poll_write` returns is in
   a compound packet starting with RR and SDES. Today it is a lone RTPFB packet. (Also assert the
   answer does not contain `a=rtcp-rsize`; today it does.)
3. **`a=rtcp-mux` absent from the remote description is accepted.** Nothing reads
   `ATTR_KEY_RTCPMUX`; `RTCRtcpMuxPolicy` is dead configuration. Reproduce: `set_remote_description`
   with an offer lacking `a=rtcp-mux` under the default (`require`) policy and expect an error (RFC
   8843 / JSEP 5.8.1); today it succeeds and RTCP is sent muxed to a peer that did not agree.
4. **An inbound compound packet is routed by its first packet only.**
   `src/peer_connection/handler/endpoint.rs:293-311` takes `destination_ssrc()` of
   `rtcp_packets.first()`. The chain delivers a marked compound whole (`keyframe.rs:68`), so a PLI
   inside `RR(no report blocks) + SDES + PLI` is dropped ("empty ssrc"), and a PLI for the video
   sender inside `SR/RR(first block: audio) + SDES + PLI(video)` reaches the application tagged
   with the audio track. Reproduce: feed `[ReceiverReport{reports: []}, SourceDescription,
   PictureLossIndication{media_ssrc: <local video sender ssrc>}]` through a connection built with
   `register_default_interceptors` and assert `poll_read` yields an RTCP message for the video
   track.
5. **SDES item types above 8 end the chunk.** `rtc-rtcp/src/source_description/mod.rs:72-82` maps
   every unknown item type to `SdesEnd`. Reproduce: unmarshal an SDES chunk `MID(15) "0"` followed
   by `CNAME "x"` (the order libwebrtc may use) and assert the CNAME item is returned; today the
   chunk is read as ended at the MID item (`mod.rs:170`), the rest of the item is then read as the
   next chunk and the whole datagram usually fails to parse, taking its SR/RR with it.
6. **`get_contributing_sources` / `get_synchronization_sources` are always empty.**
   `src/rtp_transceiver/rtp_receiver/internal.rs:36-52`: the vectors are created and never written.
   Reproduce: receive an RTP packet with two CSRCs and assert the receiver lists them.
