## Gaps, in order of importance

State: gaps 1 to 4 are closed, with new API for the offering side
(`RTCPeerConnection::replace_sctp_association`, `close_sctp_association`,
`reject_data_section` for 10.5-5). The `a=sctpmap` fallback of gap 3 is removed. Gap 5
(`a=tls-id`, 10.1-2) is closed by the DTLS area. Gap 6: the answer repeats the offer's proto
(4.4.2-1, 10.3-1) and an offer takes its proto from its candidates or the selected pair
(12.2-5, 12.2-6, 12.2-8); the RFC 4571 framing of TCP itself (8-1) is the socket owner's. Gap 7: 6.1-3, 9.2-1,
5.2-2, 6.2-1, 12.2-1 and 12.2-2 (data on pairs that differ per direction) have tests.

1. **Honour a rejected data section (10.3-12, 10.4-5), size S.** `get_application_media` (or
   its two callers) must skip a section whose port is 0. On the offering side the data channels
   created for it must then close (W3C: the channels are closed when the m-section is rejected).
   Tests: an answer with `m=application 0 UDP/DTLS/SCTP webrtc-datachannel` leaves
   `pc.sctp()` `None` and closes the pending channel; the same for the answering side of
   `tests/media_rejection_interop.rs`.
2. **Both sides initiate (9.3-1), size M.** Give the DTLS-client endpoint a server
   configuration and call `connect` in both roles, so an INIT collision is resolved by RFC 9260
   5.2.1 (the code path in `handle_init` for COOKIE-WAIT exists). Needs the endpoint to route a
   peer INIT (verification tag 0, unknown initiate tag) to the one existing association instead
   of `handle_first_packet`, and tests for simultaneous open in both orders.
3. **`sctp-port` validation (5.1-1, 5.2-1, 9.3-2, 10.2-2, 10.3-3), size S.** A data section
   without a valid `sctp-port` fails `set_remote_description` (decide whether the `a=sctpmap`
   fallback stays for legacy peers and document it); the accepting side checks the INIT's ports
   against the negotiated pair; tests that the generated offer and answer carry the attribute.
4. **SCTP association lifecycle through SDP (9.3-3 to 9.3-6, 10.3-4, 10.3-5, 10.3-9, 10.4-3,
   10.4-4, 10.5-1 to 10.5-5), size L.** Port 0 and port change: track the negotiated port pair,
   tear the association down when it changes or becomes 0, start a new one (new endpoint, new
   port numbers from an allocator instead of the constant 5000), re-run the data channel
   connected procedure, and an API to close the SCTP transport or drop the data section in an
   offer. No browser does this today; it is the largest block of literal MUSTs in this RFC and
   could instead be recorded as "not implemented, on purpose".
5. **`a=tls-id` (10.1-2), size M.** Belongs with RFC 8842 in the DTLS/JSEP area: generate a
   `tls-id`, echo/compare on renegotiation. Browsers omit it, so absence must stay accepted.
6. **Proto handling (4.4.2-1, 10.3-1, 12.2-5, 12.2-6, 12.2-8, 8-1), size S for the answer echo,
   L for TCP.** Echo the offer's proto in the answer and reject protos the engine cannot
   realize; `TCP/DTLS/SCTP` proper needs ICE-TCP and RFC 4571 framing decisions.
7. **Missing tests (6.1-3, 9.2-1, 5.2-2, 6.2-1, 12.2-1, 12.2-2), size S each.** Remote
   description without `max-message-size` gives a 64 KiB send limit; a data section with
   `a=inactive` still connects; attribute formatting; a selected-pair switch keeps the same
   association.
