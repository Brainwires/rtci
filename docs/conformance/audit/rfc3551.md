# RFC 3551: RTP Profile for Audio and Video Conferences with Minimal Control (RTP/AVP): clause audit

Spec: RFC 3551 (STD 65), July 2003; updated by RFC 5761, RFC 7007, RFC 8860. Audited at fork master
8916bc3.

Scope: the profile rules that bind a transport (sections 2, 3, 6, 7, 8), the general audio rules
(4.1 to 4.4) as far as an engine that neither encodes nor decodes can meet them, and the three
RFC 3551 encodings the default media engine offers: PCMU (4.5.14, PT 0), PCMA (4.5.14, PT 8), G722
(4.5.2, PT 9). The other encodings of 4.5 and all of section 5 (video) are not offered and are one
`n/a` row each. Encoding and decoding are the application's.

## Gaps, in order of importance

1. **The helper packetizer's audio semantics** (RFC3551-4.1-2, 4.1-3, 4.3-1). Size S. The marker bit must be a
   payloader decision: zero for audio (or first packet of a talkspurt when the caller says so), last packet of
   a frame for video. A sample-based payload split over several packets must advance the timestamp by the
   samples in each fragment. Tests: G.711 20 ms packets carry M=0; a 4000-octet PCMU buffer at MTU 1200
   yields timestamps t, t+1188, t+2376 ...
2. **RTCP bandwidth and interval per the profile** (RFC3551-2-2, 2-3, 2-4). Size L, the same work package as
   RFC 3550 gap 4 (`b=RS`/`b=RR`, 1.25% / 3.75% defaults).
3. **Payload type hygiene** (RFC3551-3-2, 3-3, 6-3). Size S. Refuse or warn on PTs 64 to 95 when registering a
   codec (RFC 5761 conflict), test rebinding of a static PT by `a=rtpmap`, and follow a mid-stream PT
   change on receive (track codec, report clock rate).
4. **CNAME on every reporting SSRC** (RFC3551-2-6). Size M, same as RFC 3550 gap 2.

## Bugs found

- **B1. Fragments of one sample-based audio payload share a timestamp.**
  `rtc-rtp/src/packetizer/mod.rs:140-157` stamps every fragment the payloader returns with `self.timestamp`;
  `G7xxPayloader` (`rtc-rtp/src/codec/g7xx/mod.rs:22-33`) splits by MTU. Reproduction:
  `new_packetizer(now, 100, 0, ssrc, Box::new(G711Payloader::default()), seq, 8000).packetize(now, &[0u8; 160], 160)`
  returns two packets with equal timestamps (88 and 72 octets); the second must be 88 ticks later.
  (`packetizer_test.rs::test_packetizer` exercises exactly this split and only counts the packets.)
- **B2. Every audio packet from the helper has the marker bit set.** Same file, line 146. Reproduction:
  packetize three 160-octet PCMU payloads at MTU 1200 and read `header.marker`: `true` three times; RFC 3551
  4.1 requires zero unless a talkspurt starts. A receiver that resets its jitter buffer or DTX state on M=1
  does so on every packet.

## Status after the RTP wire work (`conf/rtp-wire`)

B1 and B2 are fixed: a split sample-based buffer gets a timestamp per packet, and audio carries the marker only on the first packet after a silence skipped with `skip_samples`.
