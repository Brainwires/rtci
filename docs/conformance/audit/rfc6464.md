# RFC 6464: A RTP Header Extension for Client-to-Mixer Audio Level Indication

Spec: RFC 6464, December 2011 (Proposed Standard). Audited against fork master 8916bc3. Sections done: 3, 4, 5, 6
(all of the normative text).

Code: `rtc-rtp/src/extension/audio_level_extension/mod.rs` (the one-byte payload codec), `rtc-sdp/src/extmap/mod.rs:44`
(`AUDIO_LEVEL_URI`), `rtc-rtp/src/extension/mod.rs` (`HeaderExtension::AudioLevel`). Nothing in `src/` or
`rtc-interceptor/` uses the codec: the engine does not register the extension by default, does not write it, and
does not read it from received packets (`RTCRtpReceiverInternal::synchronization_sources` at
`src/rtp_transceiver/rtp_receiver/internal.rs:37` is never filled). An application can register the URI with
`MediaEngine::register_header_extension`, get an ID negotiated, and encode or decode the byte itself.

## Gaps, in order of importance

1. **Receive side (M).** RFC6464-3-8, -3-6, -4-3, -4-4. Parse `ssrc-audio-level` from received audio packets, fill
   `synchronization_sources` (level, voice activity, timestamp), honour the negotiated `vad`.
2. **Negotiation (S).** RFC6464-4-1, -4-2, -4-5, -4-6. Register the URI for audio by default, keep and echo the `vad`
   attribute (needs `ext_attr` to survive `rtp_extensions_from_media_description`, see RFC8285 gap 3).
3. **Send side (S).** An API for the application to pass a level and voice flag with an audio packet, the engine
   writing the element at the negotiated ID (the engine cannot measure audio).
4. **Tests (S).** RFC6464-3-2: an audio level through `Header::set_extension` and back in both header forms.

## Bugs found

- **A1. `getSynchronizationSources` is always empty.** `src/rtp_transceiver/rtp_receiver/internal.rs:37`, `:128-132`;
  nothing in `src/` pushes to `synchronization_sources` or `contributing_sources`. Reproduce: receive audio for a
  second, call `RTCRtpReceiver::get_synchronization_sources()`: no entry. (Also a W3C webrtc-pc 5.3 gap.)
- **A2. Unmarshal accepts an element longer than one byte without saying so.**
  `rtc-rtp/src/extension/audio_level_extension/mod.rs:31-41` reads the first byte and ignores the rest. Harmless for
  this extension; noted because the same codec would silently mis-read a `csrc-audio-level` element (RFC 6465) as a
  single level with a "voice" flag.
