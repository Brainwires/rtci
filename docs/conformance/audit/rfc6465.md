# RFC 6465: A RTP Header Extension for Mixer-to-Client Audio Level Indication

Spec: RFC 6465, December 2011 (Proposed Standard). Audited against fork master 8916bc3. Sections done: 3, 4, 5, 6
(all of the normative text; Appendix A is sample code).

Nothing in the repository implements this RFC. There is no `csrc-audio-level` URI constant (`rtc-sdp/src/extmap/mod.rs`
has `ssrc-audio-level` only), no payload codec under `rtc-rtp/src/extension/`, and the receiver's contributing-source
list (`src/rtp_transceiver/rtp_receiver/internal.rs:36`, `:122-126`) is never filled. The CSRC list itself is parsed
and marshalled (`rtc-rtp/src/header/mod.rs:115-118`, `:288-290`). An application can register the URI as a custom
extension and decode the bytes itself.

The engine is an endpoint, not a mixer; mixer-side clauses are `n/a` unless an application builds a mixer on it, in
which case they are that application's job.

Totals (MUST includes MUST NOT/SHALL; SHOULD includes SHOULD NOT/RECOMMENDED):

- MUST: tested 4 / untested 1 / partial 1 / missing 2 / violated 0 / n-a 2
- SHOULD: tested 0 / untested 0 / partial 1 / missing 0 / violated 0 / n-a 2

## Gaps, in order of importance

1. **Client side of the extension (M).** RFC6465-3-1, -4-1, -4-2, -4-3, -4-5, -5-1, -5-2. A `CsrcAudioLevelExtension`
   codec (a list of up to 15 bytes), the URI constant, registration for audio as `recvonly`, and
   `contributing_sources` filled from each received packet's CSRC list paired with the levels. Depends on extmap
   directions (RFC8285 gap 3) and shares the receive-side plumbing of RFC6464 gap 1.
2. **Guard the media type (S).** RFC6465-5-4: refuse `csrc-audio-level` and `ssrc-audio-level` for video in
   `register_header_extension`.

## Bugs found

- **C1. `getContributingSources` is always empty**, even without this extension: the CSRC list of received packets is
  parsed (`rtc-rtp/src/header/mod.rs:115-118`) and never recorded on the receiver
  (`src/rtp_transceiver/rtp_receiver/internal.rs:36`). Reproduce: receive a packet with CC=1, call
  `RTCRtpReceiver::get_contributing_sources()`: no entry. Same root cause as rfc6464.md A1.
