# Clause audit: RFC 6762 (Multicast DNS)

Spec: RFC 6762, February 2013 (current; not obsoleted). Audited against fork master 8916bc3.
Scope: what a host that publishes unique `<name>.local` address records and resolves such names
must do, the use draft-ietf-mmusic-mdns-ice-candidates makes of mDNS. Service discovery, shared
records and cache maintenance are grouped into `n/a` rows per section. All sections 2 to 22 and
Appendix C were read; none skipped.

Code: `rtc-mdns/src/proto/mod.rs` (`Mdns`: querier and responder), `rtc-mdns/src/config.rs`,
`rtc-mdns/src/socket.rs` (`MulticastSocket`, the one piece of I/O the crate ships),
`rtc-mdns/src/message/` (DNS wire format), `rtc-ice/src/agent/agent_proto.rs` (routing),
`src/peer_connection/handler/demuxer.rs`.

Shape of the implementation, which decides most verdicts: no record cache; a query is two
questions (A, AAAA) resent at a fixed interval until the first matching answer or the timeout;
the responder answers each received question at once with one multicast message per record; no
probing, announcing, goodbye, conflict detection, NSEC, cache-flush bit, QU bit, known-answer
handling or rate limit exists. "proc" rows carry no RFC 2119 keyword.

Totals (rows; MUST includes MUST NOT, SHOULD includes SHOULD NOT):

- MUST: tested 7 / untested 14 / partial 5 / missing 23 / violated 5 / n/a 16 (rows: 70)
- SHOULD: tested 7 / untested 6 / partial 0 / missing 15 / violated 0 / n/a 10 (rows: 38)
- MAY: tested 0 / untested 0 / partial 0 / missing 4 / violated 0 / n/a 2 (rows: 6)
- Procedure steps (no keyword): tested 1 / untested 0 / partial 0 / missing 0 / violated 1 / n/a 0 (rows: 2)

## Gaps, in order of importance

1. **Responder life cycle: announce, cache-flush bit, goodbye (M).** RFC6762-8.3-1, -8.3-2,
   -10.2-1, -10.2-2, -10.1-1, -8-1, -8.3-3. `add_local_name` queues an announcement, repeated
   after one second; records carry class `0x8001` in multicast responses; `close()` (and a new
   `remove_local_name`) queues TTL-0 records before clearing. Needs a response scheduler in
   `handle_timeout`, which package 2 shares.
2. **Flood control (M).** RFC6762-6-15 (one multicast per record per second), -5.2-2 (doubling
   query interval), -5.2-1 (one-second floor), -5.2-5 (20-120 ms first-query jitter), -6.3-2,
   -6.4-1 (aggregate records answering one message), plus the draft's MDNSICE-7.1-1 rate limit.
3. **Inbound message validation (S).** RFC6762-6-6 (no answers to questions inside responses),
   -18.3-2, -18.11-2 (drop non-zero OPCODE / RCODE), -6.1-4 and the record-scan bug, -6.3-1 and
   -18.1-1 (bounded but larger record budget, Additional section scanned), -16-2
   (case-insensitive names), -6-2 (class and type matching on both paths), -6-12 (source-port
   check inside `Mdns`).
4. **Unicast awareness (M).** RFC6762-5.4-3, -5.5-1, -5.5-2, -6-14, -6.7-1, -6.7-2: needs the
   datagram's destination (multicast or unicast) in `TransportContext` or a flag on
   `handle_read`, then QU replies, legacy unicast replies and refusal of unsolicited unicast
   responses. With it, MDNSICE-3.2.1-4 (send QU) becomes possible.
5. **On-link check by subnet (S/M).** RFC6762-11-2: let the application give the interface
   prefixes (or the received IP TTL / hop limit) instead of judging by address scope.
   RFC6762-11-1: `MulticastSocket` sets multicast TTL 255.
6. **Conflict handling and probing (L).** RFC6762-9-1, -8.3-5, -6.6-1, -6.6-2, -3-1, -3-2,
   -8.1-1, -8.1-2, -8.2-1, -2-1, -5-1. For UUID names probing may stay skipped; conflict
   detection (a response naming our record with other rdata) and renaming are still required,
   and application-chosen names need probing.
7. **Negative answers / NSEC (M).** RFC6762-6-4, -6.1-1, -6.1-2, -6.1-3, -6.2-3.
8. **Known-answer and duplicate suppression (M).** RFC6762-7.1-1, -7.2-2, -7.3-1, -6-10,
   -18.5-1, -6-7.
9. **Compressed SRV rdata (S).** RFC6762-18.14-4.
10. **Tests for what holds by construction (S).** RFC6762-5.2-9, -5.4-2, -6-5, -6-11, -6-16,
    -6.5-1, -8.1-3, -8.1-4, -10-1, -11-3, -16-1, -C-1, -18.1-3, -18.1-4, -18.3-1, -18.4-1, -18.5-2,
    -18.6-1, -18.11-1: one test that packs a query and an answer and asserts every header bit,
    class, TTL, ports and section counts covers most.
11. **Optional (S/M, MAY).** RFC6762-3-4, -18.1-2.

## Bugs found

- **A non-address record in the Answer section hides every record after it**
  (`rtc-mdns/src/proto/mod.rs:723-736`). `answer_header()` caches the header
  (`res_header_valid`), and the `continue` for a type other than A / AAAA neither parses nor
  skips the body, so the next `answer_header()` returns the same header until the loop's four
  turns are used. Reproduce: build a response whose Answer section is `[TXT name, A name]` (or
  NSEC first), feed it to an `Mdns` with a pending query for `name`: no `QueryAnswered`. Fix:
  `parser.skip_answer()` before `continue`.
- **Only the first four Answer records are examined** (`proto/mod.rs:722`,
  `config.rs:5` `MAX_MESSAGE_RECORDS = 3`). A responder that aggregates (RFC 6762 §6.4), for
  example a browser answering for several interface names in one message, resolves nothing past
  the fourth. Reproduce: response with five A records, the pending query's name last.
- **The fixed-IP responder answers one query twice** (`proto/mod.rs:679-684`, `707-715`). This
  crate's own querier asks A and AAAA in one message; each question pushes the name, and no
  de-duplication is done on `names_to_answer` (the `add_local_name` path has it). Reproduce:
  `MdnsConfig::with_local_names(["x.local"]).with_local_ip(v4)`, deliver a `query_now("x.local")`
  packet, count `poll_write()`: 2 identical answers.
- **The fixed-IP responder ignores the question type** (`proto/mod.rs:679-684`). Reproduce: a
  question `x.local. TXT IN` (or AAAA for an IPv4 `local_ip`) gets an A record back.
- **Questions inside responses are answered** (`proto/mod.rs:648-655`). Reproduce: a message
  with QR = 1 and one question for a registered name: an answer is queued. Two such responders
  can be made to answer each other.
- **Names are matched case-sensitively** (`proto/mod.rs:680`, `687`, `779`). `is_ice_mdns_name`
  accepts upper-case hex, so a remote candidate `61B445D2-...local` is queried in upper case; a
  responder that answers with its own (lower-case) spelling never matches the pending query, and
  this responder does not answer a query that spells its name in another case. Reproduce:
  `add_local_name("aaaaaaaa-0000-4000-8000-000000000001.local", ip)`, query
  `AAAAAAAA-0000-4000-8000-000000000001.local`: no answer.
- **Non-zero OPCODE / RCODE messages are processed** (`proto/mod.rs:636-659`). Reproduce: an
  answer packet with RCODE 3 (or OPCODE 5) and a valid A record resolves the query.
- **Query retries never back off and, without a timeout, never stop** (`proto/mod.rs:1064-1070`;
  `rtc-ice/src/agent/agent_config.rs:104` defaults `multicast_dns_query_timeout` to `None`).
  Reproduce: a bare `rtc-ice` agent in `QueryOnly`, add 32 unresolvable `<uuid>.local`
  candidates, advance time: 32 multicast queries every second, forever.
- **`MulticastSocket` sends with the default multicast TTL** (`rtc-mdns/src/socket.rs`
  `into_std`). RFC 6762 §11 asks for 255; older queriers drop anything else. Reproduce on Linux:
  capture a response from the example server and read the IP TTL (1).
