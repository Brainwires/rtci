# RFC 7714 — AES-GCM Authenticated Encryption in SRTP: clause audit

Spec: RFC 7714, December 2015 (current). Audited against fork master 8916bc3; verdicts updated for branch `conf/srtp-conformance`. Scope:
`rtc-srtp/src/cipher/cipher_aead_aes_gcm.rs`, `rtc-srtp/src/context/`, the AEAD provider trait in
`rtc-crypto/`, profile wiring in `src/peer_connection/handler/dtls.rs` and
`src/peer_connection/transport/dtls/mod.rs`. Read-only audit; no test was run. SHALL / REQUIRED count
as MUST; RECOMMENDED / NOT RECOMMENDED as SHOULD. Sections 14.1 (SDES), 14.3 and 15 (MIKEY) do not
bind a DTLS-SRTP endpoint and are one row.

## Open after `conf/srtp-conformance`

1. **Performing the re-key (M, peer connection)**: 8.4-1, 9.4-1. As RFC 3711 item 1: the context never
   cycles an index under a key and signals the re-key; the session does not act on it yet.
2. **Provider-level AEAD properties (S, `rtc-crypto`)**: 5.3-2, 13.1-4. A conformance check that
   `open_in_place` does not leave plaintext behind on a bad tag, for every provider. `rtc-srtp` drops
   the buffer on error, so nothing is released either way (5.3-1).
3. **Erasure (cannot be tested)**: 13.1-1, 13.1-3 are implemented; the verdict stays "untested" because
   freed memory cannot be inspected by a test.

## Bugs found, and fixed on the branch

- **SRTCP nonce reuse after 2^31 packets**. Fixed (RFC 3711 file, first bug); the test runs for both
  GCM profiles.
- **A valid unencrypted (E=0) AEAD SRTCP packet was rejected**. Fixed:
  `rfc7714_test.rs::unencrypted_srtcp_aead_aes_gcm_matches_rfc_7714_sections_17_3_and_17_4`. The E flag
  is associated data in both layouts, so the packet is authenticated whatever the flag says
  (`unencrypted_srtcp_aead_aes_gcm_is_still_authenticated`).
