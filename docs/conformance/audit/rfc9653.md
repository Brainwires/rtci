# RFC 9653: Zero Checksum for SCTP

Spec: RFC 9653, June 2024 (Proposed Standard). Audited against fork master 8916bc3 (`docs/conformance-audit` worktree), read-only.

RFC 9653, Zero Checksum for the Stream Control Transmission Protocol, June 2024. Not implemented and
listed under "Not implemented, on purpose": the engine always sends and requires a correct CRC32c,
which is what the RFC asks of an endpoint that has not announced the extension. The clauses that bind
such an endpoint are implemented; two of them have no test. (That was the state at the audit: the
zero checksum is implemented since, the rows below say where, and a peer connection, whose
association always runs over DTLS, announces it by default:
`the_checksum_is_zero_when_the_peer_accepts_it_and_a_crc32c_otherwise`.)

Totals (22 clauses):

- `MUST: tested 10 / untested 1 / partial 0 / missing 0 / violated 0 / n-a 4`
- `SHOULD: tested 1 / untested 0 / partial 0 / missing 0 / violated 0 / n-a 0`
- `MAY: tested 5 / untested 0 / partial 0 / missing 0 / violated 0 / n-a 1`

Levels: MUST covers MUST / MUST NOT / SHALL / REQUIRED and procedure steps the RFC words in
lower case ("must", field definitions); SHOULD covers SHOULD / SHOULD NOT / RECOMMENDED; MAY covers
MAY / OPTIONAL, each counted as a feature. Code paths are relative to `rtc-sctp/src/`; tests are
function names in that crate. `untested` with the note "by construction" means the code cannot do
otherwise but nothing would fail if it started to.

## Gaps, in order of importance

1. **Tests for the non-supporting endpoint (S).** An INIT and an INIT ACK carrying parameter 0x8001
   are accepted and the handshake completes (RFC9653-4-5); a packet with a wrong checksum and one with
   checksum zero are refused (5.3-2); an OOTB response carries a correct CRC32c (5.2-3).
2. **Zero checksum over DTLS (M).** Parameter 0x8001 with EDMID 1 (encode, decode, at most once);
   a `TransportConfig` opt-in set by the peer connection, which always runs SCTP over DTLS; announce
   it in INIT / INIT ACK; accept zero or correct checksums when announced; send zero when the peer
   announced EDMID 1, except for INIT, COOKIE ECHO and OOTB responses. Closes 4-1, 4-2, 5.1-1, 5.1-2,
   5.2-7, 5.2-8, 5.3-1, 5.3-3, 6-1, and makes 4-3, 4-4 live. Saves one CRC32c pass per packet in each
   direction with Chrome.

## Bugs found

None found. The always-CRC32c behaviour is correct for an endpoint that does not announce the
extension.
