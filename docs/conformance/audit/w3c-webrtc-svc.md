# W3C Scalable Video Coding (SVC) Extension for WebRTC (webrtc-svc): clause-level audit

Spec: Scalable Video Coding (SVC) Extension for WebRTC, W3C Editor's Draft at https://w3c.github.io/webrtc-svc/ (served copy last modified 14 September 2026). Engine: fork master 8916bc3.

Section numbers as the document refers to itself ("Section 5" for the mode table, "Section 9" for the diagrams): 1 Introduction, 2 Terminology, 3 Configuration (3.1 dictionary extension, 3.2 Behavior: 3.2.1 addTransceiver, 3.2.2 setParameters, 3.2.3 getParameters), 4 Negotiation issues, 5 Scalability modes (5.1 guidelines), 6 Examples, 7 Privacy, 8 Security, 9 Dependency diagrams.

The engine has no encoder, so "supports a mode" means: the value can be set on an encoding, validated against the codecs, read back, reported in stats, and a stream encoded that way can be packetized and described on the wire. `docs/conformance.md` lists SVC as not claimed; the rows are still counted as `missing`. The only trace of `scalabilityMode` in the engine is the statistics feed (`EncoderStatsUpdate::scalability_mode`).

## Status after the SVC work in `rtc-rtp` (branch `conf/vpx-av1-svc-1`)

Gaps 2 and 3 below are closed in `rtc-rtp`, and the table of modes and the per-codec support table
of gap 1 exist (`ScalabilityMode`, `ScalabilityMode::supported_by`, `supported_modes`). The mode
rows are `partial` because the other half of "supports a mode" is still missing: the
`scalabilityMode` member of the encoding parameters, its validation in `add_transceiver` and
`set_parameters`, reading it back, and the outbound-rtp statistic (rows SVC-3.x, gaps 1 and 4).

## Gaps, in order of importance

1. **`scalabilityMode` as an encoding parameter (M).** `SVC-3.1-1`, `SVC-3.1-2`, `SVC-3.2-1`, `SVC-3.2.1-1` to `SVC-3.2.1-3`, `SVC-3.2.2-1` to `SVC-3.2.2-5`, `SVC-3.2.3-1` to `SVC-3.2.3-4`, `SVC-5-0`: the member, a table of the 36 modes with (spatial layers, temporal layers, ratio, inter-layer dependency, S mode), a per-codec support table (VP8 / H.264 / H.265: L1Tx only; VP9 / AV1: all), the addTransceiver and setParameters checks, the "S mode with several active encodings" rule, and the value copied into outbound-rtp `scalabilityMode`.
2. **Temporal-layer signalling on the wire (M).** `SVC-5-L1T2`, `SVC-5-L1T3`: VP8 payload descriptor TID / TL0PICIDX / KEYIDX and VP9 layer indices written by the payloaders from per-frame metadata the application's encoder supplies.
3. **Spatial layers and single-stream simulcast (L).** All `SVC-5-L2*`, `SVC-5-L3*`, `SVC-5-S*`, `SVC-5-*_KEY*` rows: VP9 flexible / non-flexible layer indices and scalability structure in the payloader, one RTP frame per spatial layer with the marker on the last, AV1 dependency descriptor (`SVC-4-2`) with the template structure per mode.
4. **Reporting the configured mode back (S).** `SVC-3.2.3-3`: an application-to-engine call for "the encoder is using mode X", next to `update_encoder_stats`.
