# RFC 8826 conformance audit: security considerations for WebRTC

Spec: RFC 8826, January 2021. Audited at fork master 8916bc3. The document is a threat analysis;
it has eight BCP 14 clauses, of which five bind an engine, and a handful of lower-case
requirements that RFC 8827 turns into mechanisms. Those are recorded here as SHOULD-level rows
with their RFC 8827 counterpart, so nothing implementable is left out. Browser-only material
(origins, permission scope, UI) is n/a. Code read: as for rfc8827.md. All sections done.

## Gaps, in order of importance

1. **Negative tests for consent-before-traffic (S).** RFC8826-4.2.1-1, 4.2.1-3: one test that
   queues a data-channel message and RTP before ICE completes and asserts only STUN leaves; one
   that walks events and stats and finds no transaction id.
2. **Key export surface (S, decision).** RFC8826-4.3-3: document `serialize_pem` and the public
   `dtls_certificate` field as native-only in `docs/conformance.md`, or gate them behind a
   feature so a browser-like embedding can prove the property.
3. **Erasure of session secrets at close (S).** RFC8826-4.3.3-1: a test that the master secret and
   SRTP master keys are zeroized when the transport closes.
4. **Identity (L).** RFC8826-4.3.2.3-1: same package as RFC 8827 gap 5.
