# RFC 3550: RTP, A Transport Protocol for Real-Time Applications: clause audit

Spec: RFC 3550 (STD 64), July 2003, with the updates that change its clauses noted in the rows
(RFC 5506, RFC 5761, RFC 7022, RFC 8108 have their own files). Audited at fork master 8916bc3.

Scope: sections 3, 5, 6, 8, 10, 11 and Appendix A as they bind an RTP end system. Section 7
(translators and mixers) binds this engine only as a receiver of their output; section 9 (RTP's own
DES encryption) is replaced by SRTP in WebRTC; sections 12 to 15 bind profile authors.

The engine is a transport: the application builds the RTP packets it sends (`RTCRtpSender::write_rtp`)
or uses the helper `rtp::packetizer`. Clauses about a field the application fills are judged on
what the engine and its helper do, and say so.

## Gaps, in order of importance

1. **SDES items the parser does not know break the whole RTCP datagram** (RFC3550-6.5-4, bug B2). Size S.
   Make `SdesType` carry unknown values (`Unknown(u8)`), consume type, length and text for every item,
   stop only at type 0. Test: an SDES with CNAME followed by item type 15 (MID) inside SR+SDES parses and
   the SR is delivered.
2. **One CNAME per endpoint, and a CNAME on every packet** (RFC3550-6.1-6, 6.5.1-2, 6.5.1-3, 6.5.1-5). Size M.
   One connection CNAME (RFC 7022 form) used for every local SSRC, RTX, FEC and receiver-report SSRCs
   included, and written to `a=ssrc ... cname:`; record the remote CNAME per SSRC and expose it.
3. **SR/RR rules** (RFC3550-6.4-1, 6.4-2, 6.4-3, 6.3.8-1, 6.1-5, 6.4.2-2, 6.6-3). Size M.
   `we_sent` with the two-interval timeout (silent senders fall back to RR); SR for the RTX and FEC
   SSRCs; report blocks inside the SR of a local SSRC rather than from a random extra SSRC per remote
   stream; an empty RR when a receive-only endpoint has nothing to report; BYE for the reporting SSRCs,
   and BYE for every local SSRC from `close()` (RFC3550-6.6-2).
4. **RTCP transmission interval** (RFC3550-6.2-1 to 6.2-8, 6.3-1 to 6.3.6-1, 6.3.5-1, 6.3.5-2, A.7-1, 6.2.1-3). Size L.
   Session membership table, `rtcp_bw` from `b=RS`/`b=RR`/`b=AS` with the 5% default, `avg_rtcp_size`,
   randomisation over [0.5, 1.5] with the 1.21828 compensation, timer reconsideration, reverse
   reconsideration on BYE, source timeout after five intervals, half-interval initial delay. Under AVPF
   (RFC 4585) the same state machine carries T_rr_interval; do both together.
5. **SSRC collision handling** (RFC3550-5.1-17, 8.1-2, 8.2-1, 8.2-2, 8.2-6). Size M.
   Check every generated SSRC against local and remote ones; on an inbound packet or SDP that uses a
   local SSRC, send BYE, re-key the sender to a new SSRC and surface the change (renegotiation needed
   when `a=ssrc` lines are signalled).
6. **Compound packet discipline** (RFC3550-6.1-3, 6.1-4, 6.1-11, 6.1-13, A.2-1). Size M.
   Send feedback as a full compound packet (RR/SR + SDES + FB) unless `a=rtcp-rsize` was negotiated;
   aggregate what is due in one datagram and split at the MTU; strip RTCP padding on receive and reject
   a P bit that is not on the last packet.
7. **Receiver statistics per Appendix A** (RFC3550-6.4.1-9, A.1-1, A.1-2). Size S.
   Cumulative loss as expected minus received (signed, duplicates and late arrivals accounted), and the
   MAX_DROPOUT / MAX_MISORDER restart rule so a source restart does not freeze the report.
8. **RTP validity on the edges** (RFC3550-5.1-1, 5.1-2, 5.1-8, 5.3.1-2). Size S.
   Force V=2 on marshal (or reject other values in `write_rtp`), reject V!=2 in `Header::unmarshal`,
   drop packets whose PT is not negotiated for the receiver after the stream is bound, and add the
   missing tests.
9. **Unknown RTCP types keep their type octet; an APP packet type** (RFC3550-6.1-12, 6.7-1, 6.7-2, bug B1). Size S.

## Bugs found

- **B1. An unknown RTCP packet type is rewritten to type 0.** `rtc-rtcp/src/header.rs:78-91` maps any type
  outside 200..=207 to `PacketType::Unsupported = 0`, and both `packet.rs:110-111` and
  `raw_packet.rs:98-100` re-marshal that header, so the `RawPacket` holds `PT=0` instead of the wire
  value. Reproduction: unmarshal `[0x80, 0xD0, 0x00, 0x01, 1,2,3,4]` (PT 208) with
  `rtcp::packet::unmarshal`, marshal the result and compare: byte 1 comes back as `0x00`.
- **B2. An SDES item of a type above 8 truncates the chunk and fails the datagram.**
  `rtc-rtcp/src/source_description/mod.rs:57-69` turns the unknown type into `SdesEnd`;
  `SourceDescriptionItem::unmarshal` (`:258-264`) then returns without consuming the item's length and
  text, the chunk ends early, and `SourceDescription::unmarshal` either mis-parses the following bytes
  as a chunk or fails `chunks.len() != h.count` (`:433`). `srtp.rs:79` propagates the error, so the SR/RR
  in the same datagram is lost too. Reproduction: SR + SDES with one chunk `{CNAME "a", type 15 len 1 "0"}`
  through `rtcp::packet::unmarshal`: expect `Ok` with an SR and an SDES, get an error (or a second bogus
  chunk).
- **B3. A sender that stops sending keeps issuing sender reports.** `rtc-interceptor/src/report/sender.rs:300`
  generates an SR for every bound stream that has ever sent. Reproduction: bind a local stream, write
  one RTP packet, advance `handle_timeout` by ten intervals: ten SRs with the same counts are emitted;
  RFC 3550 6.4 requires RR (or nothing for that SSRC) after the second interval.
- **B4. SR RTP timestamp extrapolation saturates.** `report/sender_stream.rs:102`: `(secs * clock_rate) as u32`
  saturates at `u32::MAX` instead of wrapping once the stream has been idle for more than 2^32 ticks
  (13.25 h at 90 kHz, 24.8 h at 48 kHz), so every later SR carries `last_rtp + u32::MAX`. Reproduction:
  one packet, then `generate_report(now + 14 h)` twice an hour apart: both `rtp_time` values are equal.
  (Disappears with B3 fixed.)
- **B5. Cumulative loss never recovers a late packet.** `report/receiver_stream.rs:142-164`: loss is counted
  when a report is generated and never revisited. Reproduction: receive 1, 3, generate a report
  (lost = 1), receive 2, generate a report: cumulative lost is still 1; RFC 3550 6.4.1 says late packets
  are not counted as lost.
- **B6. `packetize` panics or wraps on an MTU below 12.** `rtc-rtp/src/packetizer/mod.rs:137`: `self.mtu - 12`
  on a `usize`. Reproduction: `new_packetizer(now, 8, ..)` then `packetize`: panic in debug builds, a huge
  MTU in release builds.
- **B7. Default-constructed RTP headers are sent as version 0.** `rtc-rtp/src/header/mod.rs:337` writes
  `self.version`; `Header::default().version == 0`. Reproduction: `RTCRtpSender::write_rtp` with
  `rtp::Packet { header: Header { ssrc, payload_type, ..Default::default() }, .. }`: the first octet on the
  wire is `0x00..0x3F`, which the peer's demultiplexer (RFC 7983) reads as STUN or DTLS, not RTP.

## Status after the RTP wire work (`conf/rtp-wire`)

Fixed in `rtc-rtp`: B6 (`packetize` with an MTU below 12) and B7 (a default header is version 2; another version is neither marshalled nor parsed). `check_rtp_validity` and `SourceSequence` implement Appendix A.1 as library code; the report interceptor does not use them yet. B1 to B5 are RTCP / interceptor work and are open.
