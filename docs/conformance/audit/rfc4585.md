# RFC 4585: Extended RTP Profile for RTCP-Based Feedback (RTP/AVPF)

Spec: RFC 4585, July 2006 (updated by RFC 5506 and RFC 8108; those are audited in their own files).
Audited against fork master 8916bc3. Scope: sections 2, 3 (rules and the scheduling algorithm), 4 (SDP,
as far as it binds RTP/RTCP behaviour), 5, 6 (feedback message formats), 7, 8. Section 9 (IANA) binds
nobody. Multicast-only clauses are `n/a` (WebRTC sessions are unicast, point-to-point over one 5-tuple).

How the engine is built, as far as this spec is concerned:

- There is no RTCP scheduler. Each interceptor has its own fixed timer: sender reports and receiver
  reports every 1 s (`rtci-interceptor/src/report/{sender,receiver}.rs`), generic NACK every 100 ms
  (`rtci-interceptor/src/nack/generator.rs:45`), TWCC on its own interval. None of `tp`, `tn`, `T_rr`,
  `T_rr_interval`, `allow_early`, `T_dither_max`, `avg_rtcp_size` or the RTCP bandwidth exists anywhere.
- Every interceptor emits its own RTCP datagram. A report datagram is `SR|RR [+XR]` and gets an SDES
  CNAME inserted by `InterceptorHandler::add_sdes_cname`
  (`src/peer_connection/handler/interceptor.rs:240`). A feedback datagram (NACK, PLI, TWCC, CCFB, and
  anything the application writes with `write_rtcp`) goes out alone, with no RR and no SDES, whether or
  not `a=rtcp-rsize` was negotiated.
- Feedback message codecs live in `rtci-rtcp/src/{transport_feedbacks,payload_feedbacks}`. Implemented:
  generic NACK, PLI, SLI, FIR, REMB (as AFB), RRR, TWCC, CCFB. Not implemented: RPSI, generic AFB.
  Unknown FMT values parse into `RawPacket`.
- PLI/FIR inbound are handed to the application (`rtci-interceptor/src/keyframe.rs`); PLI outbound is
  written by the application, or by the optional `IntervalPliInterceptor` (not in the default set).

## Gaps, in order of importance

1. **Feedback is sent as reduced-size RTCP unconditionally (M).** IDs 3.1-2, 3.1-4, 3.1-5, 3.1-6, 3.1-7,
   3.1-9, 6.1-5. Either (a) track whether `a=rtcp-rsize` was negotiated for the transport and, when it
   was not, wrap every feedback datagram as `RR(empty or current) + SDES CNAME + FB`; or (b) always
   build minimal compound packets. A single RTCP assembler in the peer-connection handler that takes
   what the interceptors emit in one `poll_write` round and concatenates it under one RR/SDES would
   close all seven IDs and also RFC4585-3.1-1.
2. **AVPF scheduler (L).** IDs 3.4-2, 3.4-4, 3.5-1, 3.5.1-1, 3.5.1-2, 3.5.2-1, 3.5.2-3..6, 3.5.2-8,
   3.5.2-9, 3.5.3-1..7, 3.5.4-1, 3.5.4-2, 4.2-17, 4.3-1. One RTCP timer per session implementing
   RFC 3550 6.3 (`tp`, `tn`, `avg_rtcp_size`, randomisation, RTCP bandwidth from `b=RR/RS/AS` or 5%)
   plus the RFC 4585 3.5 early-feedback state (`allow_early`, `t_rr_last`, `T_rr_interval` from
   `trr-int`), with interceptors submitting feedback to it instead of emitting datagrams. Depends on
   package 1 (the assembler). Shared with the RFC 3550 timing gaps.
3. **`a=rtcp-fb:*` wildcard (S).** ID 4.2-4. Parse `*` in `rtci-sdp/src/util/mod.rs::parse_rtcp_fb` and
   apply the feedback to every payload type of the section; write a negotiation test.
4. **One feedback originator SSRC (S).** ID 6.1-2. A single per-connection local SSRC for RR, NACK,
   PLI, TWCC and CCFB (or the SSRC of a local sender when there is one), not one random value per
   interceptor and not 0.
5. **Application-written RTCP is unchecked (S).** IDs 4.2-10, 4.2-13. Either document that
   `write_rtcp` is a raw door and the application owns negotiation, or drop FB types not negotiated
   for the target stream.
6. **RPSI and generic AFB (S).** IDs 6.3.3-1, 6.3.3.2-1, 6.4-1, 6.4-2. Add an RPSI codec; make FMT 15
   fall back to `RawPacket` when the unique identifier is not `REMB`.
7. **Marshal-side validation (S).** IDs 6.1-3, 6.2.1-1, 6.3.2-1: refuse to marshal NACK/SLI/FIR with
   no FCI entry. ID 6.3.1.2-1: decide whether an over-long PLI is rejected or tolerated and test it.
8. **Profile gate (S).** ID 4.1-1: do not bind feedback interceptors for a section whose proto is not
   `*/SAVPF` (or reject such sections outright, which JSEP allows).

## Bugs found

1. **(Fixed: RFC4585-4.2-4.) `a=rtcp-fb:* <type>` is dropped.** `rtci-sdp/src/util/mod.rs:182`: `pt_split[1].parse::<u8>()`
   fails on `*`, `media.rs:111` ignores the error, and the feedback type is lost for every codec.
   Reproduce: set a remote offer whose video section carries only `a=rtcp-fb:* nack` and
   `a=rtcp-fb:* transport-cc`; assert the negotiated codec's `rtcp_feedback` contains `nack`. It will
   be empty, and no NACK generator log is created for the stream.
2. **A NACK with more than 253 pairs cannot be marshalled, and the error kills the datagram.**
   `transport_layer_nack/mod.rs:186` (`nacks.len() + 2 > u8::MAX` returns `TooManyReports`); the length
   field is 16 bits. `NackGeneratorBuilder::with_size` allows logs up to 32768 packets, so a log of
   1024+ with alternating losses produces more than 253 pairs. Reproduce: generator with
   `with_size(1024)`, feed every second sequence number over 600 packets, fire the timer, marshal the
   result with `rtcp::packet::marshal`; expect `Err(TooManyReports)` (and `SrtpHandler::handle_write`
   propagates it as a write error).
3. **Dead overflow check in SLI marshal.** `slice_loss_indication/mod.rs:96`:
   `(self.sli_entries.len() + SLI_LENGTH) as u8 > u8::MAX` is always false (the cast truncates first).
   Harmless on the wire (length is u16) but the intended limit does not exist. Reproduce: marshal an
   SLI with 300 entries; it succeeds.
4. **A non-REMB application-layer feedback message (PSFB FMT=15) fails the whole compound packet.**
   `rtci-rtcp/src/packet.rs:130` routes every FMT 15 to `ReceiverEstimatedMaximumBitrate::unmarshal`,
   which errors when the `REMB` identifier is absent; `rtcp::packet::unmarshal` then returns `Err` and
   `SrtpHandler::handle_read` (`handler/srtp.rs:79`) drops the SR/RR that came in the same datagram.
   Reproduce: unmarshal `RR + PSFB(FMT=15, payload "ABCD....")`; expect two packets, get an error.
5. **Feedback sender SSRC is 0 in interval PLIs.** `intervalpli/generator.rs:88`. Reproduce: bind a
   `nack pli` stream, fire the timer, inspect `PictureLossIndication.sender_ssrc`.

## Status after `conf/rtcp-codec` (rtci-rtcp)

- Bug 2 fixed (NACK: the limit is the 16-bit length field). Bug 3 fixed (SLI: same). Bug 4 fixed (FMT 15 is
  REMB only when it says `REMB`; anything else is `ApplicationLayerFeedback`).
- Gap 6 closed in the codec (RPSI, generic AFB). Gap 7 closed (NACK / SLI / FIR with no FCI entry are refused on
  both paths; an over-long PLI is refused).
- Found while testing, fixed: a REMB with a zero mantissa was read as 2^(exp + 23) bit/s instead of 0; printing a
  REMB above 1000 Eb/s indexed past the unit table (a panic on peer input).
## Since the audit

- **Gaps 1, 2 and 4 closed by the RTCP session** (`rtci-interceptor/src/rtcp_session/`): every
  feedback packet leaves in a compound packet from the endpoint's SSRC, early and regular RTCP
  follow 3.5, `T_rr_interval` is honoured (1 s unless set; `RtcpSessionControl::TrrInt` for a
  negotiated `trr-int`). Bug 5 (packet sender SSRC 0) no longer reaches the wire: the session
  rewrites the packet sender of every feedback packet.
