# RFC 6188 — The Use of AES-192 and AES-256 in Secure RTP: clause audit

Spec: RFC 6188, March 2011 (current). Audited against fork master 8916bc3. Scope:
`rtc-srtp/src/key_derivation.rs`, `rtc-srtp/src/cipher/cipher_aes_cm_hmac_sha1.rs`,
`rtc-srtp/src/protection_profile.rs`, profile wiring in `src/peer_connection/handler/dtls.rs` and
`rtc-dtls/src/extension/extension_use_srtp.rs`. Read-only audit; no test was run. SHALL / REQUIRED
count as MUST; RECOMMENDED as SHOULD.

Reachability: the AES-256 counter-mode suites exist in `rtc-srtp` (`Aes256CmHmacSha1_80`,
`Aes256CmHmacSha1_32`) but **cannot be negotiated by a peer connection**: the DTLS `use_srtp` enum
knows only 0x0001, 0x0002, 0x0007, 0x0008 (`extension_use_srtp.rs:28-36`) and `update_srtp_contexts`
maps only those four (`handler/dtls.rs:543-553`). RFC 6188 registers its suites for SDP Security
Descriptions only; there is no RFC-assigned DTLS-SRTP code point for them, so within WebRTC the only
consumer of this RFC is AEAD_AES_256_GCM's KDF (RFC 7714 §11). AES-192 is absent everywhere.

## Gaps, in order of importance

1. **Decide and record AES-192 (S)** — 2-2, 3-2, 3.1-1, 4-1, 4-2, 6-2, 7-3. Not reachable from WebRTC
   (no DTLS-SRTP code point, SDES forbidden). Add to "Not implemented, on purpose" rather than build;
   building it is M (AES-192 block and CTR in both `rtc-crypto` providers, a PRF, two profiles, vectors).
2. **AES-256-CM suites are dead code for a peer connection (S, decision)** — 2-1, 4-3, 4-4. Either keep
   them as an `rtc-srtp` crate feature and say so in `docs/conformance.md`, or wire the de-facto
   `SRTP_AES256_CM_SHA1_80/32` code points (not IANA-registered by an RFC) behind an opt-in. The enum
   values 0x0003 / 0x0004 in `protection_profile.rs:39-42` suggest wire ids that DTLS never produces.
3. **Known answers (S)** — 4-4, 7-1: a vector for `Aes256CmHmacSha1_32` (tag lengths 4 / 10) and the §7.1
   keystream case.
4. **KDF choice (S, optional)** — 3.1-5.
5. **Key lifetime (S)** — 4-6: covered by the SRTCP limit fix in RFC 3711 gap 1.

## Bugs found

None in the AES-256 code paths. Related defect shared with RFC 3711: SRTCP index wrap
(`rtc-srtp/src/context/srtcp.rs:69-72`), which applies to these suites as well.
