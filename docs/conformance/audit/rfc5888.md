# RFC 5888: The SDP Grouping Framework: clause audit

Spec: RFC 5888, June 2010 (obsoletes RFC 3388; updated by RFC 8843 / 9143 for zero-port tags). Audited at
fork master 8916bc3. The engine uses the framework for BUNDLE only: `a=mid` on every m= section and one
`a=group:BUNDLE`. LS and FID m-line groups are neither generated nor interpreted.

Path legend: `sdp/mod.rs` = `src/peer_connection/sdp/mod.rs`, `pc/` = `src/peer_connection/`.

## Gaps, in order of importance

1. **Group lines by semantics (S).** RFC5888-6-4, 9.2-1 (bug shared with rfc9429.md 5.3.1-31).
2. **Use the answer's group (S).** RFC5888-9.2-4, 9.4-1: read the BUNDLE group of a remote answer; stop
   (or error on) sections it left out.
3. **mid validation (S).** RFC5888-4-1, 4-2, 9.1-3: refuse duplicate or non-token mids and answers whose
   sections do not line up with the offer.
4. **Lip-sync groups (M).** RFC5888-7-1 (with rfc9429.md gap 13).
5. **Missing-mid policy (decision).** RFC5888-6-2: the engine deliberately numbers sections; record it
   as a decision in docs/conformance.md or stop applying groups to such descriptions.

## Bugs found

- **RFC5888-6-4 / 9.2-1:** see rfc9429.md, RFC9429-5.3.1-31.
- **RFC5888-4-1:** a remote offer with two sections `a=mid:0` is accepted; both sections map to one
  transceiver (`transceiver_index_by_mid`, `src/peer_connection/sdp/mod.rs:1392`) and the answer carries
  two sections with the same mid. Reproduce: duplicate the audio section of any offer.
