# RFC 5506: Support for Reduced-Size RTCP: clause audit

Spec: RFC 5506, April 2009 (updates RFC 3550, 3711, 4585). Audited at fork master 8916bc3.

What the engine does: it writes `a=rtcp-rsize` into every media section, offer and answer
(`src/peer_connection/sdp/mod.rs:942`), never reads the attribute from a remote description, and
sends every RTCP packet that does not start with SR or RR exactly as its producer built it
(`src/peer_connection/handler/interceptor.rs:245-252`). So NACK, PLI, FIR, TWCC, CCFB, REMB and
application-written RTCP always go out as reduced-size RTCP, whatever was negotiated. Reception of
reduced-size RTCP always works.

## Gaps, in order of importance

1. **Negotiate `a=rtcp-rsize` and obey the result** (RFC5506-5-3, 5-4, 4.1-2, 4-3). Size M. Read the attribute
   from the remote description per media section (per BUNDLE group: all sections must agree), answer with
   it only when offered, expose the result in `RTCRtcpParameters::reduced_size`, and add a compound mode
   for feedback: when reduced-size was not negotiated, every feedback packet leaves as
   `RR (possibly empty) + SDES CNAME + FB`. Tests: an offer without the attribute gets an answer without
   it and a NACK on the wire is preceded by RR and SDES; with it, the NACK is bare.
2. **First RTCP is compound** (RFC5506-4-4, 4-1). Size S. Hold or wrap feedback until the first compound
   packet has gone out for the session (the simplest form: the first feedback is itself sent compound),
   and arm the report timer when the transport is up rather than on the first RTP packet.
3. **Delivery verification and fall-back** (RFC5506-4.2.1-1, 4.2.1-2, 4.2.1-3, 4.2.2-1). Size M. Track whether
   NACKs produce retransmissions and whether reports are echoed (LSR in RRs); on consistent failure
   switch the session to compound-only. Send TWCC/CCFB/REMB in a datagram that also carries a verifiable
   type, or compound.

## Bugs found

- **B1. `a=rtcp-rsize` is answered when it was not offered, and reduced-size feedback is sent regardless.**
  `src/peer_connection/sdp/mod.rs:941-942`. Reproduction: `set_remote_description` with an offer that has
  `a=rtcp-mux` but no `a=rtcp-rsize`; `create_answer` contains `a=rtcp-rsize`; then drop one inbound video
  packet and read the outbound RTCP datagram: it is a lone `TransportLayerNack` (first octet pair
  `0x81 0xCD`), with no RR and no SDES.

## Since the audit

- **Gaps 2 and 3 closed, gap 1 half**: the RTCP session sends compound packets unless told
  reduced-size was negotiated, the first packet is always compound, only NACK / PLI / FIR travel
  reduced-size, and unanswered reduced-size NACKs make it fall back. Reading and answering
  `a=rtcp-rsize` in the SDP (5-3, B1) is JSEP work; the input is `RtcpSessionControl::ReducedSize`.
