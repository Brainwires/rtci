# RFC 8305 conformance audit: Happy Eyeballs version 2

Spec: RFC 8305, "Happy Eyeballs Version 2: Better Connectivity Using Concurrency", December
2017 (current). RFC 8656 section 3.9 asks TURN clients to apply it to the server's addresses.

Audited on branch `conf/tcp-3-turn-tls`. Code: `rtc-shared/src/stream/happy_eyeballs.rs`
(`sort_addresses`, `HappyEyeballs`), `src/peer_connection/turn_streams.rs` (the engine's
TURN-over-TCP / TLS links), `examples/stream-driver/src/lib.rs` (`StreamCommand::Resolve`).

The engine is sans-I/O: name resolution is the driver's (`StreamCommand::Resolve`, answered
with every address of both families at once); the engine sorts the answer and staggers the
connection attempts. It uses this for the TURN servers it runs itself (TCP and TLS); a UDP TURN
or STUN client stays the application's. Section 6 (hostnames in literal form, NAT64 and
synthesis) and the DNS-resolver behaviour of section 3 bind the resolver: `n/a` unless the
engine has to act. Grouped rows say how many clauses they hold.
