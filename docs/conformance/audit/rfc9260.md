# RFC 9260: Stream Control Transmission Protocol

Spec: RFC 9260, June 2022 (Proposed Standard; obsoletes RFC 4960, RFC 6096, RFC 7053, RFC 8540).
Audited against fork master 8916bc3 (`docs/conformance-audit` worktree), read-only: nothing was run.

The code still follows RFC 4960 in places and says so in its comments: the initial cwnd formula
(4380 bytes, MTU instead of PMDCS) and the handling of an INIT with Initiate Tag 0. The engine is a
single-homed endpoint that runs over DTLS (RFC 8261), so multi-homing, path verification and ICMP are
`n/a`. The data path (DATA, SACK, fragmentation, reassembly, retransmission timer, fast retransmit,
graceful shutdown, abort) is implemented and mostly tested. The handshake's defensive half is not:
there is no ABORT on a refused or invalid INIT, no out-of-the-blue handling, no State Cookie MAC or
lifetime, no HEARTBEAT, and a packet with one unknown chunk or parameter is dropped whole.

Levels: `MUST` counts MUST, MUST NOT, SHALL and REQUIRED, and also procedure steps the RFC states
without a keyword (chunk and parameter action bits, the rules C1-C7, R1-R4, E1-E4, the fast
retransmit steps, state transitions). `SHOULD` counts SHOULD, SHOULD NOT and RECOMMENDED. `MAY`
counts MAY and OPTIONAL, as features. A clause the RFC repeats in two sections has a row in each.
All sections 1 to 16 are covered; sections 11 (abstract interface) and 13 to 15 have summary rows.

## Gaps, in order of importance

Sizes: S under a day, M a few days, L one to two weeks, XL more. IDs are the row IDs above.

1. **Tolerant parsing of chunks and parameters (M).** One unknown or merely unhandled item drops the
   whole packet today. Implement the two action bits for chunks (skip or stop, with or without an
   ERROR "Unrecognized Chunk Type") and for parameters (skip or stop, with "Unrecognized Parameter"
   in the INIT ACK or an ERROR), parse HEARTBEAT ACK, accept and ignore Cookie Preservative and
   Supported Address Types, ignore INIT flags, pad error causes. Rows: RFC9260-3.2-4..7,
   RFC9260-3.2.1-4..7, RFC9260-3.2.2-1..3, RFC9260-3.3.2-9, RFC9260-3.3.2.1.3-2, RFC9260-3.3.2.1.5-2,
   RFC9260-3.3.3-4, RFC9260-6.10-8, RFC9260-8.1-7. Bugs B3, B5.
2. **Stream count negotiation and invalid stream ids (S).** Pair own OS with the peer's MIS and own
   MIS with the peer's OS; bound `open_stream`; acknowledge a DATA chunk on an invalid stream and
   answer it with ERROR "Invalid Stream Identifier". Rows: RFC9260-3.3.3-15, RFC9260-5.1.1-2,
   RFC9260-5.1.1-4, RFC9260-6.5-1..3. Bugs B2, B10.
3. **Unexpected INIT, INIT ACK and COOKIE ECHO (M).** An INIT for an existing association must be
   answered (5.2.2) and must never change or close it; a failed `check()` on INIT / INIT ACK must
   discard the packet, answer with ABORT, and leave an existing association alone; restart (5.2.4
   action A) and Tie-Tags if association restart is wanted. Rows: RFC9260-5.2.2-*, RFC9260-5.2.1-*,
   RFC9260-5.2.4-*, RFC9260-3.3.2-15, -19, -23, RFC9260-3.3.3-9, -13, -18, -22,
   RFC9260-9.2-26. Bug B6.
4. **ABORT and out-of-the-blue handling (M).** Send ABORT where the RFC asks for one (refused INIT,
   invalid INIT parameters, Host Name Address, SACK of an unsent TSN, protocol violations), honour
   the T bit on ABORT and SHUTDOWN COMPLETE, answer OOTB packets (ABORT with reflected tag, SHUTDOWN
   COMPLETE for a stray SHUTDOWN ACK), stop processing a packet after an ABORT, and make `close()`
   detach the association from the endpoint. Rows: RFC9260-8.4-*, RFC9260-8.5.1-4, -5, -7, -8, -11, RFC9260-5.1-18..20, RFC9260-3.3.2-3, RFC9260-3.3.2-14,
   RFC9260-12.4-4, RFC9260-3.3.7-4, RFC9260-9.1-7. Bug B8.
5. **Congestion control to RFC 9260 (M).** Slow-start increase bounded by min(acked, L x PMDCS);
   initial cwnd from PMDCS with 4404 / 4344; `partial_bytes_acked` rules (cap, reset on T3 and when
   all data is acknowledged, count gap-acked bytes); Fast Recovery exit point = highest outstanding
   TSN; cwnd decay when idle; Max.Burst; limited overbooking of cwnd; restart T3 on fast retransmit
   of the first outstanding chunk; a reset entry point for path changes (ICE candidate pair switch).
   Rows: RFC9260-7.2-2, RFC9260-7.2.1-*, RFC9260-7.2.2-*, RFC9260-7.2.3-2, RFC9260-7.2.4-9, -11, -12,
   RFC9260-7.2.5-1, RFC9260-7.2.5.2-2, RFC9260-6.1-10, RFC9260-6.1-13.
6. **Receive-window signalling (S).** Send a window-update SACK when the application drains a closed
   window; receiver silly-window avoidance; immediate SACK when a DATA chunk is dropped for lack of
   window. Rows: RFC9260-6.2-12, RFC9260-6.2-6, RFC9260-6.2-4. Today a sender stopped at a_rwnd 0
   waits for its own T3 probe.
7. **Immediate acknowledgements (S).** SACK the first DATA of an association, DATA bundled with
   COOKIE ECHO, and DATA received in SHUTDOWN-SENT without delay; in SHUTDOWN-SENT repeat the
   SHUTDOWN and restart T2. Rows: RFC9260-5.1-21, RFC9260-5.1.5-8, RFC9260-4-7, RFC9260-9.2-14.
8. **Heartbeat (M).** HEARTBEAT timer on an idle association, HEARTBEAT ACK processing, RTT sample
   and error counting from it, `HB.interval` configuration; a default for Association.Max.Retrans.
   Rows: RFC9260-3.3.5-1..2, RFC9260-8.3-*, RFC9260-8.1-1, RFC9260-8.1-3, RFC9260-8.1-7, RFC9260-16-7, RFC9260-16-10.
9. **Shutdown robustness (S).** Limit SHUTDOWN / SHUTDOWN ACK retransmissions and close on failure,
   T5-shutdown-guard, SHUTDOWN in SHUTDOWN-PENDING, clear the count on any packet from the peer.
   Rows: RFC9260-9.2-6..8, RFC9260-9.2-16..17, RFC9260-9.2-20, RFC9260-9.2-9. Bug B12.
10. **State Cookie (M, or a decision).** MAC, timestamp and lifetime, Stale Cookie ERROR, no state
    kept between INIT ACK and COOKIE ECHO, comparison of ports and tag. Over DTLS the flooding threat
    these clauses answer does not exist, so this is a candidate for "Not implemented, on purpose";
    the half-open association that is never reaped (bug B9) needs a fix either way. Rows:
    RFC9260-3.3.3.1.1-1, RFC9260-4-2, RFC9260-5.1-7, RFC9260-5.1.3-*, RFC9260-5.1.5-1..5.
11. **Bundling (M).** Bundle control chunks with each other and with DATA (SACK with DATA, COOKIE
    ECHO / COOKIE ACK with DATA, SACK with SHUTDOWN), one response packet per received packet, and an
    MTU bound on FORWARD TSN and RE-CONFIG. Rows: RFC9260-12.4-2..3, RFC9260-6.1-16, RFC9260-6.10-1,
    RFC9260-3-2.
12. **Sender limits (S).** At most 2^16-1 ordered messages of a stream in the send window, TSN span
    guard, configuration validation (ports, OS, MIS, a_rwnd at `TransportConfig`), zero-length write.
    Rows: RFC9260-6.1-23, RFC9260-6.1-22, RFC9260-3.1-1..2, RFC9260-3.3.2-12, -16, -20, RFC9260-3.3.1-6. Bugs B4, B11.
13. **Renege handling and RTO details (S).** Miss indication and T3 start for a TSN that is no longer
    gap-acknowledged; rwnd rules B and C; one RTT sample per round trip; G1. Rows: RFC9260-6.2.1-6,
    RFC9260-6.3.2-4, RFC9260-6.2.1-2..3, RFC9260-6.3.1-5, RFC9260-6.3.1-7, RFC9260-6.3.1-10.
14. **Opaque payload protocol identifier (S).** Carry the PPID as a number end to end. Row RFC9260-3.3.1-9. Bug B7.
15. **Path MTU discovery (L).** RFC 8899 probing with PAD chunks; in "Not implemented, on purpose".
    Rows RFC9260-7.3-1, RFC9260-7.3-4 (and RFC 8261).
16. **Missing tests for implemented behaviour (M in total).** Every `untested` row: checksum
    rejection, tag 0 and port 0 rules, INIT validation, HEARTBEAT reply, unexpected INIT ACK /
    COOKIE ACK / SHUTDOWN COMPLETE, simultaneous shutdown, T2 retransmission, T1-cookie exhaustion,
    cwnd bound, loss formula of 7.2.3, I bit, SSN wrap on the sending side.

Not counted as gaps: multi-homing (5.4, 6.4, 8.2), ICMP (10) and the IANA rules (15) do not bind a
single-path, sans-I/O engine under DTLS.

## Bugs found

All by reading the code; none was executed.

- **B1. Gap Ack Blocks are wrong when the received TSNs have wrapped past the cumulative TSN, and
  two engines of this fork then kill the association.** `rtc-sctp/src/queue/payload_queue.rs:205-236`
  computes the offset with `*tsn >= cumulative_tsn` and a plain subtraction, so a wrapped TSN gets
  offset 0. The peer's `process_selective_ack` (`rtc-sctp/src/association/mod.rs:2071-2117`) looks
  up TSN `cumulative + 0`, finds nothing, returns `ErrTsnRequestNotExist`, and `handle_event` closes
  the association. Reproduction: `PayloadQueue` with `push_no_check` of TSNs `u32::MAX` and `1`,
  `get_gap_ack_blocks(u32::MAX - 2)`; expect blocks (2,2) and (4,4), get (2,2) and (0,0). End to
  end: an association whose peer initial TSN is `u32::MAX - 3`, drop the second DATA packet, send
  six messages; the sender closes with `TransportError`.
- **B2. Stream counts are negotiated crosswise.** `mod.rs:1149-1152` and `1243-1246` take
  min(own MIS, peer MIS) and min(own OS, peer OS); RFC 9260 5.1.1 pairs own OS with the peer's MIS.
  `test_assoc_handle_init` asserts the wrong mapping. Reproduction: `handle_init` with
  `num_outbound_streams: 2048, num_inbound_streams: 16`; expect `my_max_num_inbound_streams == 2048`
  (own limit permitting) and `my_max_num_outbound_streams == 16`, get 16 and 2048; a DATA chunk on
  stream 100, which the peer may use, is then discarded (and see B10).
- **B3. An unknown chunk type drops the whole packet, whatever its action bits.** `packet.rs:155`
  and `:252`. Reproduction: packet = DATA + a chunk of type 0x84 (PAD, "skip and continue") with a
  valid checksum through `Endpoint::handle`; the DATA is not delivered and not acknowledged. The
  same holds for HEARTBEAT ACK (type 5), which has a codec but no entry in the dispatch table.
- **B4. A zero-length `write` consumes a stream sequence number and sends nothing.**
  `stream.rs:553-617`: `packetize` produces no chunk for an empty payload but still increments
  `sequence_number`. The peer then waits for that SSN for ever and every later ordered message on
  the stream is held back. Reproduction: on an ordered stream `write_sctp(now, &Bytes::new(), Binary)`
  then write "x"; the receiving stream never becomes readable. (`rtc-datachannel` avoids it by
  sending a placeholder byte; the public `rtc-sctp` API does not.)
- **B5. An INIT or INIT ACK carrying a standard parameter the parser has no type for is dropped.**
  `param/mod.rs:74-78`: IPv4 Address (5), IPv6 Address (6), Cookie Preservative (9), Host Name
  Address (11), Supported Address Types (12) and ECN Capable (0x8000 is skipped, fine) fall into the
  "unknown" branch, and those with a zero high bit fail the parse. Reproduction:
  `ChunkInit::unmarshal` of an INIT with a trailing `00 0c 00 06 00 05 00 00` (Supported Address
  Types: IPv4); expect Ok, get `ErrParamTypeUnhandled`. A peer that sends parameter 12 cannot connect.
- **B6. A late copy of the peer's INIT closes an established association.** `mod.rs:1139-1146`
  returns `ErrHandleInitState` for an INIT outside CLOSED / COOKIE-WAIT / COOKIE-ECHOED;
  `mod.rs:632-634` closes the association on any error; `endpoint/mod.rs:164-168` routes a
  retransmitted INIT (same Initiate Tag) to that association. Reproduction: complete a handshake on
  a `Link`, then deliver a copy of the client's INIT to the server endpoint; the server association
  is closed with `TransportError`. The same close happens for any chunk whose `check()` fails
  (INIT ACK with a_rwnd below 1500 arriving in ESTABLISHED, for one).
- **B7. Payload protocol identifiers other than 50, 51, 53, 56, 57 are lost.**
  `chunk/chunk_payload_data.rs:53-63` maps them to `Unknown`, and `marshal_to` writes
  `Unknown as u32`, which is 58. Reproduction: unmarshal a DATA chunk with PPID 52, marshal it back;
  the PPID is 58.
- **B8. A closed association goes on processing packets.** After a User-Initiated ABORT,
  `handle_chunk` returns `Ok` (`mod.rs:1072-1078`) and the loop in `handle_inbound` (`:1033-1035`)
  handles the chunks that follow; `close()` emits no `Drained`, so the endpoint keeps routing to the
  association, and `handle_cookie_echo` accepts the CLOSED state (`:1358-1373`). Reproduction: on an
  accepting association, deliver ABORT(User-Initiated) followed by a copy of the original COOKIE
  ECHO; `is_ended()` stays true while `state()` returns ESTABLISHED and a second `Connected` event is queued.
- **B9. An INIT that is never followed by COOKIE ECHO leaves an association that is never reaped.**
  `endpoint/mod.rs:272-296`: the accepting side creates and registers the association on INIT and
  runs no timer on it. With `concurrent_associations` = 1 (the WebRTC setting) every later INIT with
  another Initiate Tag is refused for the life of the endpoint. Reproduction: deliver one INIT with
  tag X, then an INIT with tag Y; the second returns `None`.
- **B10. A DATA chunk on a stream beyond the negotiated count is never acknowledged.**
  `mod.rs:1446-1457` returns before the TSN is recorded. The peer retransmits it for ever, the
  cumulative TSN stops, and after 65535 further TSNs (`MAX_RECEIVE_TSN_WINDOW`) every chunk is
  refused. `test_handle_data_beyond_stream_limit_is_discarded` asserts the discard. Reproduction:
  extend that test: after the out-of-range chunk, send the next TSN on a valid stream and gather the
  SACK; its Cumulative TSN Ack has not moved.
- **B11. More than 65535 ordered messages of one stream fit in the send window.** The window is
  counted in user bytes (`mod.rs:3426`), so with one-byte messages a 64 KiB cwnd holds a full SSN
  cycle. Reproduction: cwnd and rwnd of 1 MiB, write 70000 one-byte ordered messages on one stream,
  drop the first DATA packet; the receiver's reassembly queue confuses SSN n with n + 65536.
- **B12. A finite `max_t2_shutdown_retrans` leaves the association in SHUTDOWN-SENT for ever.**
  `mod.rs:590-591` does not re-arm a failed timer and `mod.rs:3884-3886` only logs. Reproduction:
  `TimerConfig { max_t2_shutdown_retrans: 2, .. }`, `shutdown()` towards a silent peer, fire three
  timeouts; `poll_timeout()` is `None`, `is_closed()` is false, no event is emitted.
- **B13. Error causes are parsed and written without padding.** `chunk/chunk_abort.rs:65` and
  `chunk/chunk_error.rs:67` advance by the unpadded cause length. Reproduction: unmarshal an ABORT
  with two causes, the first with a 5-byte length; the second is read from the wrong offset and the
  packet (the ABORT) is rejected.
