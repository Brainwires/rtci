# RFC 4571 conformance audit: framing RTP and RTCP over connection-oriented transport

Spec: RFC 4571, "Framing Real-time Transport Protocol (RTP) and RTP Control Protocol (RTCP)
Packets over Connection-Oriented Transport", July 2006 (current). ICE-TCP (RFC 6544 section 3)
uses its framing for every packet on a TCP candidate pair: STUN, DTLS, SRTP and SRTCP alike.

Audited on branch `conf/tcp-1-framing`. Code: `rtc-shared/src/stream.rs` (`Framing::Rfc4571`,
`StreamDecoder`, `StreamTable`), `rtc-shared/src/tcp_framing.rs` (`frame_packet`,
`TcpFrameDecoder`). Sections done: all (2 to 4; 5 is an example, 6 to 8 are security,
IANA and references).

The engine is sans-I/O: `StreamTable` frames what it sends and splits what it reads, the
driver (the application, or the tokio reference driver `examples/stream-driver`) owns the
sockets. Section 4 defines the `TCP/RTP/AVP` profile set up with COMEDIA (RFC 4145); a WebRTC
peer never negotiates it (ICE-TCP sends SRTP over the framed ICE connection and describes it
with the `UDP/TLS/RTP/SAVPF` or `TCP/DTLS/SCTP` protos, RFC 6544 section 4.5 and RFC 8841), so
its rows are `n/a`.

Level `MUST*` marks a requirement stated without an RFC 2119 keyword; it is counted as MUST.
