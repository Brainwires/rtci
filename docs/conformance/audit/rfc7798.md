# RFC 7798: RTP Payload Format for High Efficiency Video Coding (HEVC)

Spec: RFC 7798, March 2016. Audited against fork master 8916bc3.

Scope: §4 (payload format), §5 (packetization rules), §6 (de-packetization), §7.2 (SDP, as far as
the engine matches fmtp lines and registers the default codec), §8 (feedback messages), §9, §10.
§7.1 (the media type registration's parameter semantics) binds the encoder, the decoder or the
application that writes the fmtp line; it is covered by the grouped rows RFC7798-7.1-*. The engine
is a transport without encoder or decoder: clauses that bind those are `n/a`.

Level column: MUST covers MUST / MUST NOT / SHALL / REQUIRED and the descriptive "is set" rules of
§4.1; SHOULD covers SHOULD / SHOULD NOT / RECOMMENDED; MAY covers MAY / OPTIONAL features.

Abbreviations: `h265/mod.rs` = `rtci-rtp/src/codec/h265/mod.rs`; `writer` =
`rtci-media/src/io/h26x_writer/mod.rs`; `fmtp/generic` =
`src/rtp_transceiver/fmtp/generic/mod.rs`; `rtp_codec.rs` =
`src/rtp_transceiver/rtp_sender/rtp_codec.rs`; `media_engine.rs` =
`src/peer_connection/configuration/media_engine.rs`; `packetizer` =
`rtci-rtp/src/packetizer/mod.rs`; `sample_builder` = `rtci-media/src/io/sample_builder/mod.rs`.

Two facts shape most receive-side verdicts:

- `H265Packet::depacketize` (h265/mod.rs:1119-1158) parses a payload into a structure and returns
  **the RTP payload unchanged**. It does not produce NAL units. Used as the `Depacketizer` of a
  `SampleBuilder`, the "sample" is the concatenation of raw payloads (AP and FU headers included).
- The only code that turns H.265 RTP into NAL units is `H26xWriter::write_h265` (writer:139-203),
  a file writer that never sees sequence numbers.

## Gaps, in order of importance

1. **H265-A (M): a real depacketizer.** `H265Packet::depacketize` must return NAL units (Annex B
   or length-prefixed, like `H264Packet`): single NAL units as they are, AP units split, FUs
   reassembled with the rebuilt header, PACI unwrapped (A bit, cType), types 48-63 never emitted
   (RFC7798-4.4.3-15, 4.4.4-6, 6-1, 6-2). Move the logic out of `H26xWriter` so one implementation
   serves both; accept two-byte NAL units (X-1).
2. **H265-B (S): TSCI.** Fix `H265PACIPacket::tsci` (third octet) and the `H265TSCI` accessors'
   bit positions, and test them through a real PACI payload (RFC7798-4.5-2, 4.5-3).
3. **H265-C (S): Annex B splitting.** Split on both start-code lengths in one pass, as
   `H264Payloader::next_ind` does (X-2).
4. **H265-D (M): loss-aware reassembly and the missing tests.** Sequence-number aware FU
   reassembly (RFC7798-4.4.3-12, 4.4.3-14), duplicate removal (6-3), and tests for the AP header's
   F / LayerId / TID (4.4.2-1, -3, -4), the marker bit (4.1-1), and `SampleBuilder<H265Packet>`.
5. **H265-E (M): an `H265Fmtp`.** Match on profile-space, profile-id, tier-flag, interop
   constraints and tx-mode with their defaults, leave level-id free, and stop the MIME-only
   fallback from accepting an unsupported configuration (RFC7798-7.2.2-1, -2, -5, 7.2-1, 4.3-3).
   Add SDP tests for `H265/90000` (7.2.1-1).
6. **H265-F (L): decoding order numbers.** `sprop-max-don-diff` / `sprop-depack-buf-nalus` from
   SDP, DONL / DOND on send, AbsDon and the de-packetization buffer on receive (RFC7798-4.4.1-3,
   4.4.2-10, 4.4.2-12, 4.4.3-8, 4.6-1, 5-1, 6-4, 7.1-6, 7.2.2-10).
7. **H265-G (XL): MRST / MRMT.** Multi-stream transmission, cross-stream decoding-order recovery,
   RFC 5583 dependency signalling, `recv-sub-layer-id` (RFC7798-4.3-3, 4.3-4, 7.1-3, 7.2.2-6,
   7.2.5-1). No browser implements it.
8. **H265-H (M): PACI send and RPSI.** PACI / TSCI on the send side (RFC7798-4.4.4-1), the RPSI
   feedback message (8.3-1), CRA-to-BLA type rewriting (4.4.1-2).

## Bugs found

1. **`H265Packet` does not depacketize.** `rtci-rtp/src/codec/h265/mod.rs:1157` returns
   `payload.clone()`. Reproduce: `SampleBuilder::new(.., H265Packet::default(), 90000)`, push the
   packets `HevcPayloader` makes from `VPS, SPS, PPS, IDR(> MTU)`; the popped sample starts with
   the AP header `0x60 0x01` and contains FU headers, not NAL units. An H.264 sample from the same
   pipeline is Annex B.
2. **TSCI is misread.** `h265/mod.rs:968-977`: `tsci()` uses `phes[0]` twice and never `phes[2]`,
   and packs 24 bits right-aligned while `tl0picidx()` / `irap_pic_id()` / `s()` / `e()`
   (`h265/mod.rs:1030-1070`) read a layout shifted eight bits left. Reproduce: PACI payload
   `[0x64, 0x01, 0x00, 0x38, 0xCA, 0xFE, 0x80, <nal>]` (PHSsize 3, F0=1): expect TL0PICIDX 0xCA,
   IrapPicID 0xFE, S=1; got TL0PICIDX 0, IrapPicID 0xCA, S from the wrong octet.
   `test_h265_temporal_scalability_control_information` passes because it builds `H265TSCI` by
   hand in the accessors' layout.
3. **Two-byte NAL units cannot be received.** `h265/mod.rs:471` and `:1120` reject
   `payload.len() <= 2`, so end-of-sequence (type 36, `0x48 0x01`) and end-of-bitstream (type 37)
   NAL units fail with `ErrShortPacket`, though `HevcPayloader` sends them. Reproduce:
   `H265Packet::default().depacketize(&Bytes::from_static(&[0x48, 0x01]))` is an error; in a
   `SampleBuilder` that error discards the whole sample it is part of.
4. **A lost middle or end FU yields a spliced or stale NAL unit** in `H26xWriter::write_h265`
   (`rtci-media/src/io/h26x_writer/mod.rs:166-197`). Reproduce: fragment a NAL unit into four FUs,
   write 1, 2, 4: the file gets a NAL unit missing the third chunk with F=0. Write 1, 2 and then a
   single NAL unit packet: the partial buffer stays, and `close()` (writer:108-112) writes the
   truncated fragment data after the later NAL unit.
5. **Mixed Annex B start codes merge NAL units.** `HevcPayloader::parse` (`h265/mod.rs:160-168`)
   searches for `00 00 00 01` and falls back to `00 00 01` only when there is none. Encoders
   commonly write a four-byte code before the first NAL unit and three-byte codes after. Reproduce:
   `00 00 00 01 <VPS> 00 00 01 <SPS> 00 00 01 <IDR>`: one "NAL unit" containing all three, start
   codes included, is sent (as a single packet or as FUs typed VPS).
6. **`might_need_donl` cannot be reached from negotiation.** `H265Packet::with_donl`
   (`h265/mod.rs:1102`) is set by nobody; a peer that negotiates `sprop-max-don-diff > 0`
   gets its DONL bytes treated as NAL payload. Reproduce: single NAL unit packet with a DONL
   through `H26xWriter`: the two DONL bytes are written into the NAL unit.

## Status after the RTP wire work (`conf/rtp-wire`)

Fixed in `rtci-rtp`: bugs 1, 2, 3 and 5; bug 4 for a caller that gives sequence numbers (`H265Packet::depacketize_with_sequence_number`; `H26xWriter` does not, but it no longer keeps a stale fragment buffer). Decoding order numbers are implemented on both sides (gap H265-F) except for reading the parameters from SDP (bug 6, JSEP work). MRST / MRMT, PACI sending, RPSI and an `H265Fmtp` are open.
