# RFC 5928 conformance audit: TURN resolution mechanism (client side)

Spec: RFC 5928, "Traversal Using Relays around NAT (TURN) Resolution Mechanism", August 2010
(current; RFC 7350 section 4.2 extends it for DTLS). RFC 8656 section 7.1 points to it
(row RFC8656-7.1-3).

Audited on branch `conf/tcp-3-turn-tls`. Code: `src/peer_connection/turn_streams.rs`,
`rtci-ice/src/url/mod.rs`, `examples/stream-driver/src/lib.rs` (`StreamCommand::Resolve`).

Result in one line: **the S-NAPTR / SRV algorithm is not implemented.** The engine resolves a
TURN URI's host with A / AAAA only (the driver's `Resolve`, then Happy Eyeballs, `rfc8305.md`)
on the URI's port, for TCP and TLS. NAPTR and SRV queries need a DNS client the driver would
run (a `Resolve` variant asking for records); size M, not started. The transport checks of
section 3 that apply without DNS are met.
