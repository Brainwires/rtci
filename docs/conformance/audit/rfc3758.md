# RFC 3758: SCTP Partial Reliability Extension (PR-SCTP)

Spec: RFC 3758, May 2004 (Proposed Standard, no errata applied). Audited against fork master 8916bc3 (`docs/conformance-audit` worktree), read-only.

RFC 3758, Stream Control Transmission Protocol (SCTP) Partial Reliability Extension, May 2004. It cites
RFC 2960; the code follows RFC 9260 for the base procedures, which changes nothing in this extension.
The sender and receiver procedures (3.5, 3.6) and timed reliability (4.1) are implemented and mostly
tested. The gaps are in negotiation (the engine announces PR-SCTP through RFC 5061 Supported
Extensions only, never the Forward-TSN-Supported parameter this RFC defines), in FORWARD TSN sizing and
bundling, and in two receiver paths keyed on the wrong stream setting.

Totals (66 clauses):

- `MUST: tested 24 / untested 7 / partial 4 / missing 2 / violated 2 / n-a 4`
- `SHOULD: tested 5 / untested 2 / partial 0 / missing 5 / violated 0 / n-a 2`
- `MAY: tested 3 / untested 0 / partial 0 / missing 6 / violated 0 / n-a 0`

Levels: MUST covers MUST / MUST NOT / SHALL / REQUIRED and procedure steps the RFC words in
lower case ("must", field definitions); SHOULD covers SHOULD / SHOULD NOT / RECOMMENDED; MAY covers
MAY / OPTIONAL, each counted as a feature. Code paths are relative to `rtc-sctp/src/`; tests are
function names in that crate. `untested` with the note "by construction" means the code cannot do
otherwise but nothing would fail if it started to.

## Gaps, in order of importance

1. **Negotiate with the Forward-TSN-Supported parameter (S).** Send parameter 49152 in INIT and INIT ACK
   next to Supported Extensions, and read it in `handle_init` as `handle_init_ack` already does.
   Closes RFC3758-3.3.1-1, 3.3.1-2, 3.3.2-3, 3.3.2-4, 3.3.2-5, 3.3.2-6. Add the two missing tests
   (3.3.1-3 ERROR on an un-negotiated FORWARD TSN; 3.3.2-7/-8 a peer without PR-SCTP gets no FORWARD TSN).
2. **Receiver: apply FORWARD TSN by what the peer sent, not by the local send setting (S).** Drop the
   `self.unordered` guards in `handle_forward_tsn_for_ordered` / `_for_unordered`. Closes 3.6-7, 3.6-9.
3. **Timed reliability before first transmission of ordered messages (S).** Let `pending_message_expired`
   cover ordered messages; `abandon_message` already assigns TSNs and sends FORWARD TSN for them.
   Closes 4.1-3, 4.1-5.
4. **FORWARD TSN no larger than the MTU (M).** Stop advancing Advanced.Peer.Ack.Point (or split the
   stream list) when the chunk would pass the MTU; reject more than 16382 entries. Closes 3.5-12.
5. **Tell the upper layer (S).** A public `Association::partial_reliability()` (closes 3.3.2-9, 4.2-1),
   an event for an abandoned message (4.1-4), handling of an Unrecognized Parameter / ERROR naming
   49152 (3.3.3-1..3).
6. **Bundle FORWARD TSN with DATA (M).** Needs control chunks to go through the DATA bundling path.
   Closes 3.5-16 (and makes 3.5-17 possible; 3.5-18/-19 then need a real test).
7. **Tests only (S).** 3.2-2 (non-zero flags), 3.5-15, 3.5-20 (F4), 3.5-21 (F5), 4.1-6.
8. **ENABLE_PRSCTP switch (S, optional).** A `TransportConfig` flag to stop advertising chunk 192.
   Closes 4.2-2.

## Bugs found

1. **A peer that announces PR-SCTP only with the Forward-TSN-Supported parameter in its INIT is treated
   as not supporting it** (`association/mod.rs:1177-1186`; the INIT ACK path at 1290-1296 is right).
   Every partially reliable channel to that peer silently becomes reliable. Reproduce: copy
   `handle_init_test`, give the INIT `params: vec![Box::new(ParamForwardTsnSupported)]` and no
   Supported Extensions, assert `a.use_forward_tsn`.
2. **FORWARD TSN is applied according to this side's send setting for the stream**
   (`association/stream.rs:533` and `:543`). (a) A stream whose local setting is ordered (the default,
   and the state of any stream before the DCEP OPEN is read) keeps unordered fragments the peer
   abandoned: they stay in `unordered_chunks` and count against the receive window for the life of the
   stream. Reproduce: on a default stream push an unordered beginning fragment at `peer_last_tsn+2`,
   call `handle_forward_tsn` with `new_cumulative_tsn = peer_last_tsn+3` and no streams, assert
   `get_num_bytes_in_reassembly_queue() == 0`. (b) A stream set unordered locally ignores the SSN list:
   push an ordered complete message with SSN 1, send FORWARD TSN listing (stream, SSN 0), assert the
   stream is readable; it never is.
3. **An ordered message with a lifetime is transmitted after the lifetime ran out while it waited in
   the pending queue** (`association/mod.rs:3352-3356`: the check excludes ordered beginning
