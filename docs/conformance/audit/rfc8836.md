# RFC 8836: Congestion Control Requirements for Interactive Real-Time Media

Spec: RFC 8836, January 2021 (Informational). Audited against fork master 8916bc3. Section 2 (the requirements list,
1 to 11 with every lettered sub-item) is done; sections 1, 3, 4, 5 hold no requirement on an implementation.

The requirements bind the congestion control algorithm an endpoint ships. The engine's is `Gcc`
(`rtc-interceptor/src/gcc/`, installed by `configure_congestion_control`,
`src/peer_connection/configuration/interceptor_registry.rs:774`) with `PacerInterceptor`, fed by TWCC or RFC 8888
feedback. Since the audit it is part of `register_default_interceptors` (with the RTP circuit breaker, rfc8083.md);
`register_default_interceptors_without_congestion_control` is the explicit opt-out. The rows are judged for the
default set. Details of the algorithm are in `draft-ietf-rmcat-gcc.md`.

Lower-case "should" / "must" in the sub-items are taken at the level of the word. Many requirements are properties
(fairness, stability) that only a network simulation can prove; where the mechanism exists but no test exercises the
property, the verdict is `untested`.

Totals (MUST includes MUST NOT/SHALL; SHOULD includes SHOULD NOT/RECOMMENDED):

- MUST: tested 2 / untested 5 / partial 0 / missing 0 / violated 0 / n-a 0
- SHOULD: tested 6 / untested 8 / partial 6 / missing 4 / violated 0 / n-a 0

## Gaps, in order of importance

1. **No congestion control by default (decision).** The requirements assume an endpoint always runs one;
   `register_default_interceptors` installs none. Either make `configure_congestion_control` part of the defaults or
   state in `docs/conformance.md` that RFC 8836 is the application's choice.
2. **Missing feedback as an over-use signal (M).** RFC8836-2-10 (with RFC8888-5-1, -5-2). A timeout in `Gcc` that
   cuts the target when feedback stops.
3. **Application-limited and paused senders (M).** RFC8836-2-1e, RFC8836-2-5a. Bound A_hat by 1.5 x R_hat, detect
   application-limited periods, decay the estimate with pause length.
4. **Path and interface change hook (S).** RFC8836-2-1d. A `BandwidthEstimator::on_path_change` called when the
   selected candidate pair changes.
5. **ECN as a signal (M).** RFC8836-2-7s.
6. **Start-up (M).** RFC8836-2-4, -4a: a faster start phase or padding probes.
7. **Feedback overhead (M).** RFC8836-2-8b, -8c: negotiate `a=rtcp-rsize`, adapt the interval.
8. **Coupling with the data channel, per-stream split in the pacer, DSCP (L).** RFC8836-2-6a, -6b, -2-9.
9. **A simulation suite for the property requirements (L).** RFC8836-2-1a, -1b, -1f, -1g, -2, -2s, -2a, -3, -3s, -3a,
   -5, -11: two-flow and TCP-competition scenarios, jitter, VAD gaps and an AQM (CoDel) bottleneck on top of
   `rtc-interceptor/tests/path_simulator/`.

## Bugs found

None beyond those recorded in `draft-ietf-rmcat-gcc.md` (G1 to G5), `rfc8888.md` (B6) and
`draft-holmer-rmcat-transport-wide-cc-extensions.md` (T1, T2), which are what make rows 1c, 1e, 6 and 8c fall short.
