# RFC 8835: Transports for WebRTC

Spec: RFC 8835, January 2021 (Standards Track). Audited against fork master 8916bc3.
Sections covered: 3 and 4 (all normative text). Scope note: this file belongs to the RTP/RTCP area.
Clauses whose substance is ICE, TURN, DTLS or SCTP are listed so the checklist is complete, with the
verdict this pass could establish by reading the code; the clause-level proof for them is in the
ICE/TURN/DTLS/SCTP audit files (RFC 8445, 8656, 6544, 8261, 8831, 8832, 8833). Where this pass did
not read the test, the verdict is `untested` or `partial`, never `tested`.

The engine is sans-I/O: it opens no socket, gathers no interface address and sets no IP header
field. It can only meet a socket-level clause by telling the application what to do with each
datagram (as it does for ECN in `TransportContext::ecn`).

## Gaps, in order of importance

1. **Unbundled transports (XL, decision D2).** RFC8835-4.2-7, 4.2-9 (and RFC 8834 4.4-1).
2. **DSCP and priority (M).** RFC8835-4.1-1, 4.2-1 to -5: `priority` / `networkPriority` on
   encodings and data channels; a DSCP field next to `ecn` in `TransportContext` filled per RFC
   8837 Table 1 (one value for all SCTP, one per TCP connection); weighted pacing by priority.
3. **DTLS ALPN, RFC 8833 (S).** RFC8835-3.5-6.
4. **ALTERNATE-SERVER (S).** RFC8835-3.4-11: follow a 300 in the TURN client and for STUN
   server-reflexive gathering.
5. **I-DATA (L, on-purpose gap).** RFC8835-3.5-3.
6. **Happy Eyeballs for ICE, RFC 8421 (S).** RFC8835-3.2-3.
7. **Tests for the transport matrix (M).** The ten `untested` rows: IPv6-only, TURN over TCP and
   TLS, dual-family TURN allocations. These need the real-network environment (Linux CI).
8. RFC 6062 TURN TCP allocations (L, optional, on-purpose gap).
