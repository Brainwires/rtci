# Clause audit: RFC 8828 (WebRTC IP Address Handling Requirements)

Spec: RFC 8828, January 2021 (current). Audited against fork master 8916bc3.

RFC 8828 binds the component that opens sockets and enumerates interfaces. This engine is
sans-I/O: it opens no socket, reads no interface list or routing table, sends no STUN or TURN
gathering request and never sees a proxy; the application gathers candidates and hands them to
`RTCPeerConnection::add_local_candidate`. So the four modes are chosen and carried out by the
application, and most clauses are `n/a` for the engine. What the engine does own is the set of
controls an application needs to carry a mode out: candidate-type filtering
(`RTCIceTransportPolicy::Relay`, `AgentConfig::candidate_types`), network-type filtering
(`SettingEngineBuilder::with_network_types`) and mDNS hiding (`MulticastDnsMode`). Those are
audited as "proc" rows (no RFC 2119 keyword of their own).

Code: `src/peer_connection/internal.rs:73-93` (policy to `candidate_types`),
`src/peer_connection/mod.rs:2255-2268` (`set_configuration`), `rtci-ice/src/agent/mod.rs:457-477`
(`add_local_candidate` filters), `src/peer_connection/configuration/setting_engine.rs`.

## Gaps, in order of importance

1. **Mode 3 at the peer-connection level (S).** RFC8828-5.2-P2: a `SettingEngine` option for
   the agent's `candidate_types` (for example "no host candidates"), so an application that
   forwards everything it gathers can still run Mode 3 without filtering itself.
2. **Dead filter options (S).** RFC8828-5.2-P4: remove the commented-out `with_interface_filter`
   / `with_ip_filter`, or document in `docs/conformance.md` (decision D3) that interface and
   address selection is the application's.
3. **Test the network-type filter (S).** RFC8828-5.2-P3: add a local and a remote candidate of
   an excluded type and assert neither is kept.
4. **Say so in the docs (S).** `docs/conformance.md` has no row for RFC 8828; add one stating
   that address-handling modes are the application's and naming the three controls above.

No clause of RFC 8828 is missing or violated in the engine itself: its eleven keyworded clauses
bind the gatherer.

## Bugs found

None specific to RFC 8828. The privacy defects in the mDNS hiding that Mode-2-with-mDNS relies
on are in `draft-ietf-mmusic-mdns-ice-candidates.md` ("Bugs found").
