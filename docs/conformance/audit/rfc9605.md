# RFC 9605 (Secure Frame, SFrame): clause-level audit

Spec: RFC 9605, "Secure Frame (SFrame): Lightweight Authenticated Encryption for Real-Time Media", August 2024 (https://www.rfc-editor.org/rfc/rfc9605.txt). Engine: fork master 8916bc3.

Finding: the repository has no SFrame implementation. `grep -ri sframe` over every crate finds nothing: no header codec, no key derivation, no cipher suite, no RTP payload format. Every clause that binds an SFrame sender or receiver is therefore `missing`. Clauses addressed to the key management system or the application's KID strategy are `n/a` (the engine would take keys, not manage them). The W3C Encoded Transform API makes SFrame a built-in transform (`RTCRtpSFrameEncryptor`, `RTCRtpSFrameDecryptor`), so the audit counts RFC 9605 as binding the engine. The rows `RFC9605-X-*` at the end are not RFC clauses: they say what the engine exposes today for an application that brings its own SFrame, which is the only way to use SFrame with this engine now.

All RFC 2119 sentences of the RFC are listed (19), plus the unkeyworded format and algorithm definitions of section 4 as MUST-level features, since an implementation that does not follow them does not interoperate.

## Gaps, in order of importance

1. **An SFrame implementation (L).** `RFC9605-4.2-1`, `RFC9605-4.3-1` to `RFC9605-4.3-4`, `RFC9605-4.4.1-2`, `RFC9605-4.4.2-1`, `RFC9605-4.4.3-1`, `RFC9605-4.4.4-1` to `RFC9605-4.4.4-4`, `RFC9605-4.5-1` to `RFC9605-4.5-5`, `RFC9605-4.5.1-1`, `RFC9605-7.4-1`, `RFC9605-9.1-1`, `RFC9605-9.3-1`, `RFC9605-9.3-2`, `RFC9605-9.4-1`, `RFC9605-9.4-2`: a sans-I/O `rtc-sframe` crate (header codec, HKDF derivation, the five suites through the existing crypto provider, encrypt / decrypt contexts with a counter per key, a key store with roles), checked against the RFC's Appendix C test vectors.
2. **RTP packetization of SFrame (M).** `RFC9605-6.1-1`, `RFC9605-6.2-1`, `RFC9605-X-3`, `RFC9605-X-5`: the SFrame RTP payload format (per-frame with generic fragmentation, per-packet), its SDP signalling and a transceiver switch (shared with `ENCTRANS-2.1-1`).
3. **Layers and forwarding metadata (M).** `RFC9605-6.1.3-1`, `RFC9605-X-6`: one ciphertext per layer and the dependency descriptor (shared with the SVC package).
4. **A test for opaque payloads (S).** `RFC9605-X-4`.
