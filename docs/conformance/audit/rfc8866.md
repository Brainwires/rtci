# RFC 8866: SDP: Session Description Protocol: clause audit

Spec: RFC 8866, January 2021 (obsoletes RFC 4566). The code's comments and state machine still cite
RFC 4566 section 5 and draft-ietf-rtcweb-jsep-24; behaviour follows the RFC 4566 grammar where the two
differ (rows `RFC8866-4566-n`). Audited at fork master 8916bc3.

Scope: the engine parses remote SDP (`rtc-sdp`, reached through `set_remote_description`) and generates
its own (`new_jsep_session_description`, `populate_sdp`). Each row says which direction it judges
("gen" = generated SDP, "parse" = parser). WebRTC is unicast and RTP-over-ICE, so multicast, session
announcement and user-interface clauses are `n/a`.

Path legend: `session.rs` = `rtc-sdp/src/description/session.rs`, `media.rs` =
`rtc-sdp/src/description/media.rs`, `lexer` = `rtc-sdp/src/lexer/mod.rs`, `util` = `rtc-sdp/src/util/mod.rs`,
`sdp/mod.rs` = `src/peer_connection/sdp/mod.rs`, `pc/` = `src/peer_connection/`. Tests named
`description_test::x` are in `rtc-sdp/src/description/description_test.rs`.

## Gaps, in order of importance

1. **Default direction (S).** RFC8866-6.7-2, 6.7-1: treat a missing direction as sendrecv, read a
   session-level direction, in `set_remote_description`, `set_local_description` and `track_details_from_sdp`.
2. **fmtp with spaces (S).** RFC8866-5.14-11, 6.15-1: split `a=fmtp` at the first space only.
3. **k= lines (S).** RFC8866-5.12-2, 5.12-1: drop on parse, never marshal.
4. **Grammar conformance of the parser (M).** RFC8866-5.6-1 (repeated e= / p=), 4566-3 (z= per time
   description), 9-3 (value trimming), 9-4 (out-of-order media lines), 9-5, 9-8, 9-9, 5.3-2 (empty s=),
   5.8-6, 5.7-1, 5.7-7, 5.13-2 (NUL), 5-5 (bare CR, blank lines). Decide strict or tolerant per case and
   test each.
5. **Session-level inheritance (S).** RFC8866-5.13-5 (see rfc9429.md 5.2.1-55).
6. **ptime / maxptime / bandwidth (M).** RFC8866-6.4-1, 6.5-1, 5.8-7, 5.8-3: parse, expose, apply.
7. **Unregistered source attributes (S).** RFC8866-5.13-3: stop writing `mslabel` / `label`.
8. **Charset and extensibility (S, or declare out of scope).** RFC8866-6.10-1, 6.10-2, 5-1, 5.2-4, 5.2-5,
   5.7-3: either accept non-UTF-8 octets and unknown nettype / addrtype (ignore the section), or list them
   under "Not implemented, on purpose".
9. **Informational attributes (S).** RFC8866-6.3-1, 6.8-1, 6.9-1, 6.13-1, 6.14-1: optional; no engine use.
10. **Tests only.** Every `untested` row; notably 5-3 (unknown type letter), 5.1-1 (`v=1`), 6.6-5.

## Bugs found

- **RFC8866-6.7-2: a media section without a direction attribute breaks the answer.**
  `set_remote_description` (`src/peer_connection/mod.rs:1562`) skips the section when
  `get_peer_direction` is `Unspecified`; `generate_matched_sdp` (`src/peer_connection/internal.rs:523`)
  then finds no transceiver for the mid. Reproduce: remote offer `m=audio 9 UDP/TLS/RTP/SAVPF 111` with
  mid, rtpmap, ICE and fingerprint but no `a=sendrecv`; `create_answer` returns
  `ErrPeerConnTransceiverMidNil`. In a remote answer the same omission leaves `current_direction` unset.
- **RFC8866-5.14-11: `a=fmtp` parameters containing a space are dropped.** `parse_fmtp`
  (`rtc-sdp/src/util/mod.rs:160`) requires `split_whitespace().len() == 2`. Reproduce:
  `a=fmtp:96 level-asymmetry-allowed=1; packetization-mode=1; profile-level-id=42e01f` then
  `MediaDescription::codecs()[96].fmtp` is empty, so H.264 profile matching falls back to a partial match.
- **RFC8866-5.12-2: a received `k=` line is kept and re-serialized** (`session.rs:1234`, `338`).
- **RFC8866-5.6-1: a second `e=` or `p=` line is a parse error** (`session.rs:724`, `760`). Reproduce: two
  `e=` lines before `t=`.
- **RFC8866-5.3-2 / 9-3: values are trimmed.** `read_value` (`rtc-sdp/src/lexer/mod.rs`) trims, so `s= `
  (the form RFC 8866 recommends) becomes the forbidden empty `s=` when marshalled, and an attribute value
  with meaningful leading or trailing space changes.
- **RFC8866-6.6-1: `a=rtpmap:96 VP8` (no clock rate) is accepted with clock rate 0** (`util:140`).
