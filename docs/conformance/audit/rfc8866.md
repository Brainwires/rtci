# RFC 8866: SDP: Session Description Protocol: clause audit

Spec: RFC 8866, January 2021 (obsoletes RFC 4566). Audited at fork master 8916bc3; the rows changed by
the `rtci-sdp` conformance work (the RFC 8866 parser and serializer, the typed attributes) are judged at
that branch. The parser followed the RFC 4566 grammar where the two differ; it now follows RFC 8866, and
the rows `RFC8866-4566-n` say what became of each difference.

Scope: the engine parses remote SDP (`rtci-sdp`, reached through `set_remote_description`) and generates
its own (`new_jsep_session_description`, `populate_sdp`). Each row says which direction it judges
("gen" = generated SDP, "parse" = parser). WebRTC is unicast and RTP-over-ICE, so multicast, session
announcement and user-interface clauses are `n/a` unless the parser checks them anyway.

Path legend: `session.rs` = `rtci-sdp/src/description/session.rs`, `media.rs` =
`rtci-sdp/src/description/media.rs`, `common.rs` = `rtci-sdp/src/description/common.rs`, `lexer` =
`rtci-sdp/src/lexer/mod.rs`, `grammar.rs` = `rtci-sdp/src/grammar.rs`, `attribute/` =
`rtci-sdp/src/attribute/`, `util` = `rtci-sdp/src/util/mod.rs`, `sdp/mod.rs` =
`src/peer_connection/sdp/mod.rs`, `pc/` = `src/peer_connection/`. Tests named `description_test::x`,
`grammar_test::x`, `audit_bugs_test::x` and `browser_test::x` are in `rtci-sdp/src/description/`;
`attribute_test::x` is `rtci-sdp/src/attribute/attribute_test.rs`.

## Gaps, in order of importance

1. **Default direction (S), engine.** RFC8866-6.7-2, 6.7-1: treat a missing direction as sendrecv, read a
   session-level direction, in `set_remote_description`, `set_local_description` and
   `track_details_from_sdp`. rtci-sdp now reads the attribute at both levels (`direction()`).
2. **Call `SessionDescription::validate` on remote descriptions (S), engine.** RFC8866-5.7-1 and
   rfc9429.md 5.8-1: the check exists in rtci-sdp; `set_remote_description` does not use it yet.
3. **Session-level inheritance (S), engine.** RFC8866-5.13-5 (see rfc9429.md 5.2.1-55).
4. **ptime / maxptime / bandwidth (M), engine.** RFC8866-6.4-1, 6.5-1, 5.8-7, 5.8-3: rtci-sdp parses them
   (`ptime()`, `maxptime()`, `bandwidth_of`); nothing applies or writes them.
5. **Several c= lines in one media description (S).** RFC8866-5.7-7: only the last is kept, because
   `MediaDescription` has one `connection_information` field. Layered multicast only.
6. **Charset (S, or declare out of scope).** RFC8866-6.10-1, 6.10-2, 5-1: a=charset is not supported;
   text that is not UTF-8 is refused. Candidate for "Not implemented, on purpose".
7. **Domain names (S).** RFC8866-5-7: the section 9 `FQDN` rule is checked, the RFC 1035 label rules are
   not.
8. **Informational attributes (S).** RFC8866-6.3-1, 6.8-1, 6.9-1, 6.14-1: kept as unknown attributes; no
   typed reading, no engine use.
9. **Session version (S), engine.** RFC8866-5.2-3 (rfc9429.md bug 5.2.2-1). Closed by jsep-75.
10. **Tests only.** The remaining `untested` rows: 6.1-1, 6.2-1, 5.8-4 (things the engine never writes),
    6.7.1-1, 6.7.3-1, 6.7.4-1 (RTCP whatever the direction), 7-5.
