# RFC 8854: WebRTC Forward Error Correction Requirements

Spec: RFC 8854, January 2021 (Standards Track). Audited on branch `conf/fec-7-rfc8854` (from
`conf/fec-6-browser-cell`); RFC8854-5.2-1 and 5.1-1 revised on `conf/fec-13-flexfec-offer`. Whole document covered: sections 4 to 8 carry the requirements; 1 to
3 define terms, 6 makes no recommendation for application data, 9 states the FEC / SRTP
ordering of RFC 3711 without a keyword (the engine applies FEC before SRTP on the way out and
after it on the way in: `Slot::FecWireImage`, `handler/srtp.rs`), 10 has no IANA action.
RECOMMENDED and NOT RECOMMENDED count as SHOULD (RULES.md).

The engine is a transport: it carries what an encoder produced and gives a decoder what
arrived. Choosing an encoding (Opus in-band FEC, a lower-bitrate redundant encoding, AMR's
FEC) is the application's encoder's work and those rows are `n/a` with that reason; what the
engine signals, packetizes, recovers and paces is audited here.

Default differs: RFC 8627 section 1.1.7 requires of an answerer: "If a peer supporting both FLEX FEC and other RTP retransmission methods (see [RFC4588]) receives an Offer including both FLEX FEC and another RTP retransmission method, it MUST respond with an Answer containing only FLEX FEC" (tested both ways: `the_answerer_keeps_only_flexfec_unless_told_to_keep_rtx_too`), so `video/flexfec` in every default offer would leave two default peers without RTX for video. Coordinator decision (fec4, 2026-11-24): `conflict`, today's form (not offered, RTX kept) the default; RFC 8854's form is `DefaultInterceptorOptions::video_flexfec` (`configure_video_flexfec`), on in `StrictRfc` (profile row `fec.video-flexfec`). The draft browsers implement (`flexfec-03`, under libwebrtc field trials) has no such rule and is answered with RTX. Not a W3C / RFC 9429 conflict in the sense of RULES.md: RFC 9429 5.3.1 asks for `rtx` in an answer only "for each primary codec where RTP retransmission should be used"; and without RTX the NACK responder still retransmits on the media SSRC (and RFC 8627 R=1 retransmission exists, `FlexFecSendBuilder::with_retransmissions`), so flipping the default is the option's value plus the browser cells |
