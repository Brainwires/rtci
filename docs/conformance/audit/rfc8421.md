Spec: RFC 8421 (BCP 217), July 2018. Audited against fork master 8916bc3.

Totals (8 rows):

- SHOULD: tested 5 / untested 0 / partial 0 / missing 0 / violated 0 / n-a 2
- MAY: tested 0 / untested 0 / partial 0 / missing 0 / violated 0 / n-a 0

The RFC has one BCP 14 keyword, a MUST quoted from RFC 8445. Its recommendations are written
with lowercase "should"; as a Best Current Practice that RFC 8445 §5.1.2.1, §5.1.2.2 and
Appendix B.9 make a SHOULD, they are listed here at SHOULD level.

Update (`conf/ice-10-loss`): `rank_local_candidates` and `Agent::add_local_candidates` rank
candidates gathered together with section 4's IPv6 head start; the agent ranks candidates added
one at a time in their order, interleaving the families (`rank_local_candidate`). What follows
is the audit as first made.

The engine computes a candidate's priority from its type and transport only: the local
preference is the constant 65535 for UDP and `2^13·direction + 8191` for TCP
(`rtc-ice/src/candidate/mod.rs:498-559`). The address family, the interface and the number of
candidates are not inputs. An application can only bypass this by writing a whole priority
into the candidate string it adds.

## Gaps, in order of importance

1. **WP-8421-1: local preference as an input (M).** One work package with RFC 8445's
   WP-ICE-5: give `CandidateConfig` (and the peer-connection API that adds local candidates)
   a local preference, or have the agent assign one when a candidate is added: unique per
   candidate of a type (5-2), IPv6 and IPv4 interleaved with an IPv6 head start (4-1, 4-2,
   4-3), an optional "unreliable" flag that sorts a candidate last (3-1, 5-3). Because the
   application gathers, the agent is the only place that sees the whole candidate set, so
   the assignment belongs in `Agent::add_local_candidate`; candidates already signalled keep
   their priority.
2. The ordering only matters once checks are paced and ordered (`rfc8445.md` WP-ICE-1).

## Bugs found

Fixed on `conf/ice-1-bugs`: 1 (`agent_rfc8445_test.rs::test_local_candidates_of_one_type_get_unique_interleaved_priorities`).

1. **Equal priorities for different candidates** (`rtc-ice/src/candidate/mod.rs:330-344`).
   Reproduce: build two UDP host candidates, 192.0.2.1 and 2001:db8::1 (or two IPv4
   addresses on two interfaces), without a priority: `priority()` is 2130706431 for both.
   RFC 8445 §5.1.2 requires unique priorities; the pair priorities then tie as well, and
   which pair the controlling agent nominates depends on insertion order.
