## Gaps, in order of importance

1. **Stamp RID on outgoing simulcast packets (M).** RFC8852-3.3-1. Same work package as RFC7941 gap 1: the sender
   knows each encoding's RID and the negotiated extension ID.
2. **RTCP SDES RtpStreamId and RepairedRtpStreamId (S).** RFC8852-3.1-1, -3.2-1: add items 12 and 13 to `SdesType`,
   skip unknown items by length, and bind an SSRC from an SDES RID when no header extension has done so.
3. **Validate the values (S).** RFC8852-3-5: accept only ASCII alphanumerics; ignore the extension otherwise.
4. **Repaired-RID for FEC (S).** RFC8852-3-2: a FlexFEC stream that announces itself by repaired-RID is treated as
   RTX today (`bind_repair_by_rrid` writes `coding.rtx`).
5. **Tests (S).** RFC8852-3-3 (one RID under two MIDs), RFC8852-3.3-1 (two-byte header).

## Bugs found

- **R1. Any stream announced by repaired-RID is bound as RTX.** `src/peer_connection/handler/interceptor.rs:620-640`:
  the repair SSRC is stored in `coding.rtx` whatever codec its payload type names. Reproduce: negotiate
  `video/flexfec-03`, send a FEC packet with MID and repaired-RID on an undeclared SSRC: later packets on that SSRC
  resolve through `rtx_primary_for` only if the payload type is RTX, otherwise they are bound as a second "RTX" SSRC
  and never reach the FEC decoder.
- See also rfc7941.md S1 (RTCP SDES items above 8 break the chunk) and S2 (RID must be negotiated for MID to be
  read), which both act on this RFC's identifiers.
