# RFC 3711 — The Secure Real-time Transport Protocol (SRTP): clause audit

Spec: RFC 3711, March 2004 (current; updated by RFC 5506, 6904, 9335). Audited against fork master
8916bc3. Scope: `rtc-srtp/`, `rtc-shared/src/replay_detector/`, `src/peer_connection/handler/srtp.rs`,
the keying glue in `src/peer_connection/handler/dtls.rs` (`update_srtp_contexts`). Read-only audit; no
test was run. SHALL / REQUIRED count as MUST; RECOMMENDED / NOT RECOMMENDED count as SHOULD;
OPTIONAL counts as MAY. Sections 6 (adding transforms), 7 (rationale) and 11 (scenarios) carry almost
only requirements on documents or on key management; they are listed as single rows.

Totals (124 rows):

- MUST: tested 55 / untested 10 / partial 7 / missing 6 / violated 3 / n-a 12
- SHOULD: tested 7 / untested 3 / partial 3 / missing 1 / violated 0 / n-a 2
- MAY: tested 3 / untested 0 / partial 1 / missing 8 / violated 0 / n-a 3

## Gaps, in order of importance

1. **SRTCP key lifetime (S)** — RFC3711-3.4-16, 9.2-4 (and RFC 7714 §9.4, §13.1). `encrypt_rtcp` wraps
   the index to 0 after 2^31-1. Return `ErrExceededMaxPackets` instead, mirror the SRTP test.
2. **Key-exhaustion handling at session level (M)** — 3.3.1-11, 8.1-1, 9.2-2, 9.2-3, 11.3-1,
   3.2.1-5. Count packets per master key (both directions' contexts), surface an event before the limit
   and either re-handshake DTLS or fail the transport; today a stream silently errors per packet. Also
   make the receiver honour the overflow flag (3.3.1-10 note).
3. **Replay protection defaults and bounds (S)** — 3.3.2-1, 3.3.2-2. Make `Context::new` default the
   remote side to a 64 window (or split local/remote constructors), reject windows 1..=63 in
   `SettingEngineBuilder`, and add a test that goes through `update_srtp_contexts`.
4. **Secret hygiene (S)** — 3.2.1-4. `SessionKeys` to `SecretVec`, drop `Debug`/`Clone` (or redact),
   zeroize session salts.
5. **32-bit tag offered by default (S)** — 5.2-3, 7.5-1, 9.5-3; plus 9.2-1 (prefer 256 over 128 or
   document why not). Remove `SRTP_AES128_CM_HMAC_SHA1_32` from `default_srtp_protection_profiles` (opt-in).
6. **SRTCP index starts at 1 (S)** — 3.4-6. Post-increment; update `test_encrypt_rtcp_separation` and the
   known-answer cases that set the index.
7. **RTCP bandwidth accounting (M)** — 3.4-18, 3.4-19. Needs an RFC 3550 §6.3 `avg_rtcp_size` first (RTCP
   area); then add the profile's SRTCP overhead.
8. **Tests for implemented-but-untested clauses (S)** — 3.2.3-1/2, 3.3-4/6 (logging), 3.4-2, 4.1.1-4,
   5.2-2 / 9.5-2 (known answer for `_32` SRTCP tag length), 8-4, 9.1-1/2, 10-1, B-1 (Appendix B.2 vectors).
9. **NULL cipher (S, on purpose)** — 4.1.3-1, 5.1-3. Mandatory in RFC 3711, forbidden by RFC 8827.
   Record as a decision in `docs/conformance.md` rather than implement.
10. **MKI, `<From,To>`, non-zero kdr, f8, unencrypted SRTCP on send (L, on purpose)** — 3.1-3, 3.4-10,
    3.2.1-7, 8.1-2, 8.1.1-1, 4.3.1-3, 4.1.2-1, 3.4-12, 3.3.1-12. None is reachable through DTLS-SRTP as
    WebRTC uses it; MKI is already in "Not implemented, on purpose".

## Bugs found

- **SRTCP index wraps instead of stopping** (`rtc-srtp/src/context/srtcp.rs:69-72`). Reproduction: in
  `context/srtcp_test.rs`, `ctx.set_index(ssrc, 0x7FFF_FFFE)`; `encrypt_rtcp` (index 0x7FFFFFFF) succeeds;
  the next `encrypt_rtcp` returns a packet with index 0 instead of an error; a third call after
  `set_index(ssrc, 0)` shows index 1 reused with the same key (identical keystream for equal plaintext).
- **First SRTCP packet carries index 1, not 0** (`srtcp.rs:69`). Reproduction: fresh context,
  `encrypt_rtcp` once, read the trailer: `0x80000001`. Already pinned by `test_encrypt_rtcp_separation`.
- **Receiver follows a ROC wrap** (`rtc-srtp/src/context/srtp.rs:34` discards the overflow flag).
  Reproduction: receiver `set_roc(ssrc, u32::MAX)`, decrypt seq 0xFFFF, then a packet with seq 0 protected
  under ROC 0 by a second sender context with the same key: it is accepted (expected: refused, the 2^48
  limit).
- **`Context::new` with `None` options has no replay protection**, contradicting the doc comment in
  `rtc-srtp/src/config.rs:32-36` ("ReplayProtection is enabled on remote context by default").
  Reproduction: `Context::new(k, s, profile, None, None, crypto)`, decrypt the same protected packet
  twice: both succeed. Sessions are not affected (`handler/dtls.rs:587-603` passes windows).
- **Replay window below 64 accepted** (`setting_engine.rs:1061`, `1088`). Reproduction:
  `with_srtp_replay_protection_window(1)` builds; a packet reordered by one position is then dropped.
