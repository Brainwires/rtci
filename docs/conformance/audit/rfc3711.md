# RFC 3711 — The Secure Real-time Transport Protocol (SRTP): clause audit

Spec: RFC 3711, March 2004 (current; updated by RFC 5506, 6904, 9335). Audited against fork master
8916bc3; verdicts updated for branch `conf/srtp-conformance`. Scope: `rtc-srtp/`, `rtc-shared/src/replay_detector/`, `src/peer_connection/handler/srtp.rs`,
the keying glue in `src/peer_connection/handler/dtls.rs` (`update_srtp_contexts`). Read-only audit; no
test was run. SHALL / REQUIRED count as MUST; RECOMMENDED / NOT RECOMMENDED count as SHOULD;
OPTIONAL counts as MAY. Sections 6 (adding transforms), 7 (rationale) and 11 (scenarios) carry almost
only requirements on documents or on key management; they are listed as single rows.

Totals (124 rows):

- MUST: tested 84 / untested 1 / partial 1 / missing 0 / violated 0 / n-a 7
- SHOULD: tested 10 / untested 2 / partial 2 / missing 0 / violated 0 / n-a 2
- MAY: tested 9 / untested 0 / partial 0 / missing 3 / violated 0 / n-a 3

## Open after `conf/srtp-conformance`

The rows above carry the state of the branch. What is still not "tested":

1. **Acting on key exhaustion (M, peer connection)**: 3.3.1-11, 8.1-1, 9.2-3, 9.2-4, 11.3-1. `rtc-srtp`
   counts packets per master key, refuses the packet past the limit in both directions, and raises
   `ContextEvent::KeyLifetimeExpiring` / `KeyExhausted`. `src/peer_connection/handler/srtp.rs` has to
   poll `Context::poll_event` and either start a new DTLS handshake or fail the transport, and should
   call `Context::set_key_lifetime` with 2^31 packets (RFC 5764 section 4.1.2).
2. **Replay window bound in the builder (S, peer connection)**: 3.3.2-2 note.
   `with_srtp_replay_protection_window(1..=63)` should be refused when it is called, not when DTLS
   completes; and a test should go through `update_srtp_contexts` (3.3.2-1 note).
3. **32-bit tag offered by default (S, peer connection)**: 5.2-3, 7.5-1, 9.5-3, 9.2-1.
4. **RTCP bandwidth accounting (M, RTCP area)**: 3.4-18, 3.4-19.
5. **Untested, outside `rtc-srtp`**: 3.2.3-1, 3.2.3-2, 3.3-4, 3.3-6 (logging), 3.4-2, 8-4, 9.1-1, 9.1-2,
   10-1.
6. **Not implemented, on purpose**: `<From, To>` key lifetimes (3.2.1-7, 8.1.1-1; re-keying is by MKI)
   and AES-f8 (4.1.2-1; optional, specified for the owner in `docs/conformance.md`).

## Bugs found, and fixed on the branch

Each was reproduced with a failing test on fork master 8916bc3 before the fix.

- **SRTCP index wrapped instead of stopping** (keystream reuse under one key). Fixed: per-master-key
  packet counts; `key_lifetime_test.rs::srtcp_is_refused_after_2_pow_31_packets_under_one_key`.
- **First SRTCP packet carried index 1, not 0**. Fixed: the RFC's 0;
  `key_lifetime_test.rs::first_srtcp_packet_carries_index_zero`. Interop is unaffected (a receiver
  takes any first index).
- **Receiver followed a ROC wrap**. Fixed: `key_lifetime_test.rs::receiver_does_not_follow_a_roc_wrap`.
- **`Context::new` with `None` options had no replay protection**. Fixed: `None` is a 64-packet window;
  `profiles_test.rs::a_context_without_options_has_replay_protection`.
- **Replay window below 64 accepted**. Fixed in `rtc-srtp` (`srtp_replay_protection` /
  `srtcp_replay_protection` return an error); `profiles_test.rs::a_replay_window_below_64_is_refused`.
