## Gaps, in order of importance

State: gaps 1 and 2 are closed (6.5-2, 6.6-8; 52 / 54 are treated as unsupported, 6.6-7 stays
`missing`). Gap 3 is closed: weighted fair queueing is the default scheduler and, with
interleaving, chooses for every chunk (6.4-2). Gap 4: the path change reaches SCTP and the
packet size follows the path (5-3, 5-6); nothing probes the path MTU (5-5 stays `missing`, 5-4
`partial`). Gap 5 is closed: interleaving is announced by default, and messages are held to
16 KB on an association without it (6.1-9, 6.6-9, 6.6-10). Gap 6: 6.2-2, 6.6-6, 6.6-11 and
6.7-4 have tests; 6.1-4 and 6.2-1 are `rtc-sctp`'s. Gap 7 is `rtc-sctp`'s.

1. **Reject a duplicate stream id (6.5-2), size S.** `create_data_channel` returns an error
   (W3C: `OperationError`) when `negotiated: Some(id)` names a stream the registry already
   holds; also refuse id 65535. One unit test.
2. **Close on receive errors (6.6-8, 6.6-7), size S-M.** In `DataChannelHandler::handle_read`,
   a message whose PPID is not one of 50/51/53/56/57, and a DCEP message that fails to parse on
   an existing channel, reset the stream (the `reset_stream` path already exists) and close the
   channel instead of delivering binary data or returning an error. Decide whether to reassemble
   52 / 54 (optional, deprecated) or treat them as unsupported.
3. **Apply the channel priority (6.4-2), size S for the wiring, L with I-DATA.** Call
   `Stream::set_priority(priority)` when a stream is opened from a local or peer OPEN
   (`sctp.rs` `handle_write` / `apply_peer_reliability`) and for negotiated channels; decide
   whether WFQ becomes the default. True RFC 8260 semantics need I-DATA (see 6.1-9).
4. **Path MTU discovery and path-change handling (5-3, 5-4, 5-5, 5-6), size L.** Same work
   package as RFC 8261 gap 1; 5-6 is its interim S-sized part (default MTU for IPv4).
5. **Message interleaving (6.1-9, 6.6-9) and the 16 KB rule (6.6-10), size XL / S.** I-DATA is
   the RFC 8260 audit's package. Until then either cap sends at 16 KB by default (a behaviour
   change no browser makes) or record the deviation as a decision.
6. **Missing tests (6.1-4, 6.2-1, 6.2-2, 6.6-6, 6.6-11, 6.7-4), size S each.** INIT content
   (Supported Extensions, 65535 streams); peer SHUTDOWN closes every channel; empty payload
   reaches the application empty; small message is not delayed; close then reopen on the same id.
7. **Check the peer's RE-CONFIG support before resetting (6.1-4 note), size S.** Record whether
   the peer's Supported Extensions list carried RE-CONFIG and fail the close cleanly (or fall
   back to closing locally) when it did not.

## Bugs found

State: all three confirmed by a failing test and fixed. 1:
`a_second_negotiated_channel_on_a_stream_in_use_is_refused`. 2:
`a_message_with_an_unsupported_ppid_closes_the_channel`. 3:
`the_priority_of_a_local_channel_weighs_its_stream`,
`the_priority_in_the_peers_open_weighs_the_stream`.

1. **A second negotiated channel on a used stream id is accepted** (6.5-2).
   `src/peer_connection/mod.rs:2367-2370`, `src/data_channel/registry.rs:57-70`. Reproduce:
   unit test calling `create_data_channel("a", negotiated: Some(4))` then
   `create_data_channel("b", negotiated: Some(4))`; today both succeed and
   `registry.handle_of_stream(&4)` names "b", so inbound data for "a" is delivered to "b" and
   closing either one tears down the shared stream. Expected: the second call fails.
2. **Messages with an unsupported PPID are delivered as binary data** (6.6-8).
   `src/peer_connection/handler/datachannel.rs:356-364`. Reproduce: handler test in the style
   of `an_empty_message_counts_as_zero_bytes_received`, feeding a `DataChannelMessage` with
   `ppi: PayloadProtocolIdentifier::Unknown` (what PPID 52, 54 or any other value decodes to);
   today `poll_read` yields a `DataChannelEvent::Message { is_string: false, .. }`. Expected:
   no message, a stream reset queued, the channel closing. A peer still using the deprecated
   partial PPIDs gets each fragment surfaced as a separate, wrong message.
3. **The DCEP priority never reaches the scheduler** (6.4-2).
   `rtc-sctp/src/association/stream.rs:338` has no caller outside `rtc-sctp`. Reproduce: with
   `with_sctp_weighted_fair_queueing(true)`, open two channels with priorities 128 and 1024,
   queue equal backlogs behind a small cwnd, and compare bytes sent per stream; today the split
   is even.
