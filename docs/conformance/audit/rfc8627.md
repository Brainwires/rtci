# RFC 8627: RTP Payload Format for Flexible Forward Error Correction (FEC)

Spec: RFC 8627, July 2019 (Standards Track). Audited at fork master 8916bc3. Sections covered: 1.1.2,
1.1.7, 1.1.8, 4, 5, 6, 7, 8, 9 (all sections with requirements on an endpoint).

**Status of the implementation.** RFC 8627 is not implemented. It is in the "Not implemented, on purpose"
table of `docs/conformance.md`; per the audit rules every clause is still counted as `missing`. The code
implements draft-ietf-payload-flexible-fec-scheme-03 (`video/flexfec-03`), audited separately in
[draft-ietf-payload-flexible-fec-scheme-03.md](draft-ietf-payload-flexible-fec-scheme-03.md). The
constant `MIME_TYPE_FLEX_FEC` (`video/flexfec`, `media_engine.rs:175`) exists, an application may register
it and it is then written to SDP, but `is_flexfec03_mime_type` (`rtp_codec.rs:343`) keeps it away from the
draft-03 coder (test `rtp_codec_flexfec_test.rs::rfc_8627_flexfec_is_not_the_draft_03_coder`), so no RFC
8627 packet is ever produced or decoded.

The Note column says what the draft-03 coder does for the same clause: **same** (the draft-03 behaviour
would satisfy the RFC clause unchanged), **differs** (the wire format or rule is different), or **neither**
(draft-03 code does not do it either). A verdict other than `missing` is given only where the engine's
generic SDP handling binds for `video/flexfec` itself.

Where the two wire formats differ (the reason a draft-03 round trip proves nothing about RFC 8627):

| Field | draft-03 (implemented) | RFC 8627 |
|---|---|---|
| Protected SSRCs | `SSRCCount` + 24 reserved bits + `SSRC_i` words inside the FEC header | CSRC count and CSRC list of the repair packet's RTP header |
| Fixed FEC header before the first mask | 20 bytes | 12 bytes |
| k bit | 1 = this is the last mask (libwebrtc reading) | 1 = another mask follows, 0 = last |
| Third mask | k bit + 63 bits (packets 46..108, 109 in all) | 64 bits, no k bit (packets 46..109, 110 in all) |
| R=1 | F=1: retransmission, parsed differently | R=1 F=0: retransmission; R=1 F=1 reserved |
| F=1 | M / N offsets | L (columns) / D (rows), with defined 1-D and 2-D meanings |
| Subtype | `flexfec-03` in practice | `flexfec` |

## Gaps, in order of importance

1. **RFC 8627 coder next to the draft-03 one (L).** RFC8627-4.2.1-3, 4.2.2.1-1 to -6, 6.2-1, 6.2-2, 6.3.x: an
   encoder and decoder for the flexible-mask variant (R=0 F=0) with CSRC-list source identification, the
   RFC's k-bit polarity and the 110-bit third mask, selected by `video/flexfec` exactly as `flexfec-03`
   selects the draft-03 coder. The XOR arithmetic, coverage and decoder state of `fec/draft03` are reusable;
   the header writer/parser and `mask3` selection are not.
2. **Receiver completeness the RFC makes mandatory (L).** RFC8627-1.1.8-2, 1.1.8-3, 4.2.2.2-1 to -3,
   4.2.2.3-1, 6.3.1.2-1, 4.2.2.1-4: decode F=1 (L/D rows and columns, 1-D and 2-D), R=1 retransmissions and
   several SSRCs per repair packet. Unlike in draft-03, a conforming RFC 8627 receiver MUST handle all of
   them.
3. **`repair-window` (M).** RFC8627-5.1-3, 5.2.1-1, 1.1.2-1, 1.1.8-1, 4.2.2.2-3: generate and parse the
   parameter, reject an offer whose window cannot be supported, size buffers from it, bound what is sent.
4. **Repair stream as an RTP source (M).** RFC8627-4.2.1-8 to -11, -13: random initial sequence number,
   send-time timestamps, SR/SDES CNAME for the repair SSRC, collision handling (shared with draft-03).
5. **Negotiation rules (S).** RFC8627-1.1.7-1 (answer FlexFEC only when offered with RTX; note libwebrtc
   does not do this, decide and document), RFC8627-7-2 (in-band SSRC mapping), RFC8627-5.2.1-1 (do not
   answer `video/flexfec` while nothing decodes it, even when an application registered it).
6. **Adaptive protection (M).** RFC8627-8-1 to -3 (shared with draft-03).

## Bugs found

None specific to RFC 8627, since nothing implements it. One hazard: an application that registers
`MIME_TYPE_FLEX_FEC` gets `video/flexfec` offered and answered with no coder behind it (RFC8627-5.2.1-1);
the peer then spends bandwidth on repair packets that are dropped at `handler/endpoint.rs:276`
("drop rtp packet"). Reproduction: register `video/flexfec` on both media engines, negotiate, and observe
that the answer contains the payload type while no interceptor binds an FEC flow. The defects of the
draft-03 coder are listed in the draft-03 audit.
