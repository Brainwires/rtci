# RFC 9628: RTP Payload Format for VP9 Video

Spec: RFC 9628, March 2025 (Standards Track). Audited against fork master 8916bc3.
Sections covered: 3 (PG definition), 4 (payload format), 5 (feedback), 6 (parameters, SDP), 8, 9.
All normative text.

Code: `rtc-rtp/src/codec/vp9/mod.rs` (`Vp9Payloader`, `Vp9FrameHeader`, `Vp9Packet`), tests in
`vp9/vp9_test.rs` and `vp9/vp9_depacketizer_fields_test.rs`; frame assembly in
`rtc-media/src/io/sample_builder/mod.rs`; negotiation in `src/rtp_transceiver/fmtp/generic/mod.rs`
and `src/peer_connection/configuration/media_engine.rs` (VP9 `profile-id=0` at PT 98,
`profile-id=1` at PT 100).

What the payloader does. One call is one VP9 frame, taken to be one picture (single spatial
layer). Default (`flexible_mode == false`): it parses the uncompressed header; a key frame gets
`I=1 B/E V=1 Z=1` with an SS of one layer (`N_S=0, Y=1, G=1, N_G=1, TID 0, U=1, R=1, P_DIFF=1`),
any other frame gets `I=1 P=1 Z=1`. If the header does not parse, or `flexible_mode` is set, it
sends `I=1 F=1 P=0` with no layer and no reference indices. PID is always 15 bits. Layer indices
(L, TID, U, SID, D, TL0PICIDX) and flexible-mode reference indices are never written: spatial and
temporal scalability cannot be sent ("Not implemented, on purpose": SVC). The depacketizer parses
every field.

## Gaps, in order of importance

1. **Flexible mode tells the truth about prediction (M).** RFC9628-4.2-3, 4.2-31, 4.2-9. Parse the
   uncompressed header in flexible mode too (frame type, intra_only, refresh/ref indices) and set
   P and the P_DIFFs, or remove flexible mode as a fallback: a frame whose header does not parse
   should be an error to the caller, not a silent switch of F.
2. **Layer indices and SVC on send (L, on-purpose gap).** RFC9628-4.2-20, -23, -28, 4.1-2, 3-1:
   per-frame inputs (SID, TID, U, D, end-of-picture, TL0PICIDX, the PG) so the PID, marker, L
   octets and SS describe what the encoder did.
3. **`profile-id` default and VP9 fmtp matching (S).** RFC9628-6-5, 6.1.2-1, -2, -4: a VP9 fmtp
   type with `profile-id` defaulting to 0 and `max-fr`/`max-fs` excluded from matching.
4. **Depacketizer strictness (S).** RFC9628-4.2-8 (ignore F when I=0), 4.2-27 (SID up to 7), stale
   `width`/`height`.
5. **`max-fr` / `max-fs` (S).** RFC9628-6-1, 6-3: parse, expose, and decide whether the default
   codecs advertise them.
6. **Intra-only frames (S).** RFC9628-4.2-3, non-flexible side: read `intra_only` so such frames
   get P=0 (w4 lists it as a known limit).
7. **Tests (S).** PID wrap (4.2-17), SS on resolution change (4.2.1-8), VP9 offer/answer with
   profiles (6.1.2-1, -3).
8. RPSI and LRR (M, optional). RFC9628-5.1-1, 5.3-1.

## Bugs found

1. **A VP9 codec without `profile-id` matches any profile.**
   `src/rtp_transceiver/fmtp/generic/mod.rs:8-23`. Reproduce: a `MediaEngine` with only
   `video/VP9` `profile-id=2`; remote offer `a=rtpmap:98 VP9/90000` and no fmtp. RFC 9628 6 says
   the offer is profile 0, so the answer must reject the payload type; the engine answers with it.
2. **F is honoured with I=0.** `rtc-rtp/src/codec/vp9/mod.rs:410`. Reproduce: depacketize
   `[0x50, 0x02, 0xAA]` (I=0, P=1, F=1). The descriptor is one octet and the payload is
   `[0x02, 0xAA]`; the code reads `0x02` as a P_DIFF and returns `[0xAA]`.
3. **The payloader changes F mid-stream.** `vp9/mod.rs:109-117`. Reproduce: default
   `Vp9Payloader`; payload a valid key frame (first octet `0x8F`, or `0x8B` when fragmented: non-flexible), then a buffer
   whose first two bits are not `10` (or a key frame header declaring width 65536): the second
   frame's first octet is `0x9C` (F=1, P=0), a flexible-mode non-predicted frame in a
   non-flexible stream. Receivers that track the mode per key picture mis-parse or treat it as a
   switch point.
4. **Stale SS resolution.** `vp9/mod.rs:606-618`: `width`/`height` are replaced only when Y=1.
   Reproduce: one `Vp9Packet`; depacketize a packet with V=1, Y=1 (640x480), then one with V=1,
   Y=0; `width` still reads `[640]` for the second packet although it announced none. Same for a
   later packet with V=0 (all SS fields keep the last SS, which may be intended as "current SS";
   if so it should be documented and `ns`/`y`/`g` treated the same way).
5. **Flexible mode always claims P=0** (row 4.2-3). `vp9/mod.rs:149`. Reproduce:
   `Vp9Payloader { flexible_mode: true, .. }`, payload an inter frame (uncompressed header with
   frame_type 1): first octet is `0x9C`; it must have P set (`0xDC`) and at least one P_DIFF.
