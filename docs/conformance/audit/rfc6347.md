# RFC 6347 conformance audit: Datagram Transport Layer Security version 1.2

Spec: RFC 6347, January 2012 (obsoleted by RFC 9147 for new versions; DTLS 1.2 is what the engine speaks, see `rfc9147.md`; updated by RFC 7507, 7905, 8996, 9146).

Audited at fork master 8916bc3. Code read in full: `rtc-dtls/src/{conn,endpoint,handshaker,state,config}`, `flight/`, `fragment_buffer/`, `handshake/`, `record_layer/`, `crypto/`, `cipher_suite/`, `prf/`, `extension/`, and the tests beside them and under `rtc-dtls/tests/`. All sections (4.1 to 5) done. Rows marked "Implicit" are requirements the text states without a keyword (wire formats, the state machine). Handshake content rules inherited from TLS 1.2 are in `rfc5246.md`.

## Status of the gaps and bugs

The rows above carry the current verdicts; the lists below are the audit as it was made at 8916bc3.

- Fixed, each with a test named in its row: bugs 5, 6, 8, 9, 10, 13 and 14. Gaps 1, 2, 3, 4, 9 and 10 are closed, and gap 8 but for RFC6347-4.2.7-3 (not done, on purpose) and -4.2.1-3 (the RFC contradicts itself; kept).
- Gaps 5, 6 and 7 are closed in a server `Endpoint`: the cookie exchange is stateless, the answers take their sequence numbers from the ClientHello, and a ClientHello with a valid cookie on a live address starts a new association (4.2.8).
- Found on the way: a client in its first flight answered any handshake record that delivered nothing with a fatal internal_error (`conn_transport_test.rs::an_out_of_place_plaintext_handshake_message_does_not_block_the_genuine_one`).

## Gaps, in order of importance

1. **Unauthenticated records that still end a handshake (S).** RFC6347-4.1.2.7-1, -4.1.2.7-3, -4.2.1-18, -5-1.
   Discard an epoch-0 application-data record instead of answering it with a fatal alert, and treat a
   ClientHello with a wrong cookie as one without a cookie (answer with HelloVerifyRequest again).
   Split `unpack_datagram` so that a malformed trailing record does not drop the valid ones before it.
2. **Fragment reassembly with overlapping ranges (M).** RFC6347-4.2.3-5. Replace the offset-chain
   walk with a byte-coverage map (the caps on fragments and messages stay).
3. **Retransmission timer backoff (S).** RFC6347-4.2.4.1-2, -4.2.4.1-3. Double from 1 s to 60 s, keep
   the value until a flight is answered without loss; decide the give-up rule in time rather than a
   count of seven (7 x 1 s ends a handshake that a browser would still complete).
4. **Record size limits (S).** RFC6347-4.1.1.1-3, -4.1.1-2, -4.1.1.1-4. Refuse writes above 2^14, cut
   handshake fragments at `mtu - 25` (and the AEAD overhead in epoch 1), report the per-suite record
   expansion.
5. **Record sequence numbers of HelloVerifyRequest and the first ServerHello (S).** RFC6347-4.2.1-9,
   -4.2.1-11. Echo the ClientHello's record sequence number.
6. **Stateless cookie (M).** RFC6347-4.2.1-7, -4.2.1-10. HMAC(secret, address, ClientHello
   parameters), with a rotating secret; removes the 256-association table. The current stateful
   design is bounded and documented, so this is conformance work, not a fix.
7. **New association on the same 5-tuple (M).** RFC6347-4.2.8-1, -4.2.8-3. A ClientHello on a live
   association starts a second handshake beside it and replaces it after Finished.
8. **Alert hygiene (S).** RFC6347-4.1.2.1-5 (bad_record_mac for a failed decrypt), -4.2.7-2, -4.2.7-3,
   -4.2.1-3 (HelloVerifyRequest version 1.0; needs a decision since Chrome and Firefox accept both).
9. **PMTU backoff of handshake fragments (M).** RFC6347-4.1.1.1-9. Halve the fragment size after
   repeated unanswered retransmissions.
10. **Tests for what is implemented but unpinned (S).** The `untested` rows: send-side
    fragmentation, the transcript known-answer (4.2.6-2), second ClientHello equality, replay-window
    minimum of 32 (also a `partial`: add the bound), default timer and window values.

## Bugs found

Numbering is shared with `rfc5246.md` so that one list covers the DTLS 1.2 stack.

5. **A plaintext application-data record during the handshake fails the association.**
   `rtc-dtls/src/conn/mod.rs:1025`. Reproduction: start a handshake between two `Endpoint`s, and
   before it completes feed the server `17 fe fd 00 00 <6-byte seq 1000> 00 01 00` from the
   client's address; expect no event and a completing handshake, observe `ErrAlertFatalOrClose`,
   a queued fatal alert and `is_connection_failed`. Needs no keys, only the peer's address.
6. **A ClientHello with a wrong cookie fails the association.** `rtc-dtls/src/flight/flight2.rs:86`.
   Reproduction: server sends HelloVerifyRequest; feed a ClientHello with message_seq 1 and 20 bytes
   of junk as cookie; the association fails, the endpoint replaces it on the next datagram, and the
   genuine second ClientHello (message_seq 1) is then never accepted by the fresh association
   (it expects message_seq 0). One spoofed datagram denies the handshake.
   `conn_test.rs::test_failed_flight_is_not_parsed_again` pins the failing behaviour.
8. **Handshake datagrams exceed the configured MTU by 25 bytes.** `rtc-dtls/src/conn/mod.rs:498`.
   Reproduction: `with_mtu(1200)` and a certificate chain above 1200 bytes (RSA-2048 with a long
   SAN list); assert every `poll_transmit` datagram is at most 1200 bytes; the first fragment is 1225.
9. **Application writes above 65535 bytes produce a corrupt record length.**
   `rtc-dtls/src/record_layer/mod.rs:55` (`content.size() as u16`) and the `r_len as u16` in each
   cipher. Reproduction: `Endpoint::write` with 70000 bytes on a completed association; the record
   header claims 4464 + overhead; the peer drops it. Expected: an error for anything above 2^14.
10. **Overlapping fragments never reassemble.** `rtc-dtls/src/fragment_buffer/mod.rs:245`.
    Reproduction: push fragments [0,100) and [50,150) of a 150-byte message; `pop` keeps
    returning `ErrEmptyFragment`.
13. **One malformed trailing record drops the whole datagram.** `rtc-dtls/src/record_layer/mod.rs:108`
    with `conn/mod.rs:560`. Reproduction: append 5 junk bytes to a datagram holding a valid
    ServerHello flight; `read` returns `ErrInvalidPacketLength` and none of the records is processed.
14. **The retransmission timer never backs off.** `rtc-dtls/src/handshaker.rs:229`. Reproduction:
    drop every server datagram, record the instants `poll_timeout` returns; they are 1 s apart, and
    the handshake fails after 8 s. RFC 6347 expects 1, 2, 4, 8, ... up to 60 s.
