# RFC 8859: A Framework for SDP Attributes When Multiplexing: clause audit

Spec: RFC 8859, January 2021. Audited at fork master 8916bc3. The RFC classifies every registered SDP
attribute for use inside a BUNDLE group; its normative text is the category rules of section 4 plus the
per-attribute tables of sections 5 to 13. This audit lists: the category rules; one row per attribute
that the engine writes or interprets (the `RFC8859-A-n` rows, MUST level because section 4 binds every
bundled m= section), with the category taken from RFC 8859 or from the RFC that registered the attribute
later (RFC 8285, 8830, 8840, 8841, 8842, 8851, 8853, 8858, 9143, 9335); and one row for everything else.

How to read the attribute rows: "gen" is what `populate_sdp` writes into a BUNDLE group, "recv" is how a
remote description's value is used. RFC 9143 7.1.3 adds where IDENTICAL and TRANSPORT attributes may
appear; that placement is judged in rfc9143.md (RFC9143-7.1.3-3), not again in each row here.

The categories themselves are data in `rtci-sdp` since the rtci-sdp conformance work:
`rtci_sdp::attribute::mux` holds the category and level of every attribute of RFC 8859 section 15.2.2 and
of the attributes registered later (`mux::attribute`, `mux::bandwidth`, `mux::rtcp_fb`,
`mux::group_semantics`, `mux::ssrc_group_semantics`, `mux::source_attribute`; tests
`attribute_test.rs::the_mux_table_has_the_category_of_every_attribute_webrtc_uses` and its neighbours).
Nothing in the engine reads it yet: the rows below still judge what `populate_sdp` writes and what a
remote description's values are used for.

Path legend: `sdp/mod.rs` = `src/peer_connection/sdp/mod.rs`, `pc/` = `src/peer_connection/`,
`me.rs` = `src/peer_connection/configuration/media_engine.rs`.

## Gaps, in order of importance

1. **Validate remote descriptions against the categories (M).** RFC8859-4.3-1, 4.7-1, A-2, A-3, A-5,
   A-13, A-17, A-18: refuse (or deterministically resolve) a BUNDLE group whose sections disagree on an
   IDENTICAL attribute, map one payload type to two codec configurations, or map one extmap id to two
   URIs.
2. **TRANSPORT attributes from the tagged section (S).** RFC8859-4.5-1, A-20, A-19: `a=setup` (and
   fingerprints) from the tagged m= section, then the session level.
3. **Bandwidth (M).** RFC8859-4.4-1, A-31: read b=AS / TIAS, sum AS across the bundle.
4. **Attributes not implemented (S each).** RFC8859-A-4, A-21, A-28, A-32 (see rfc9429.md gaps 12, 15).
