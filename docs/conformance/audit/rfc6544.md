# RFC 6544 conformance audit: TCP candidates with ICE

Spec: RFC 6544, "TCP Candidates with Interactive Connectivity Establishment (ICE)", March 2012
(current; written against RFC 5245, read here with RFC 8445 / RFC 8839 in its place). Framing is
RFC 4571.

Audited at fork master 8916bc3. Code: `rtc-ice/src/tcp_type/mod.rs`,
`rtc-ice/src/candidate/mod.rs`, `rtc-ice/src/agent/mod.rs`, `rtc-ice/src/agent/agent_selector.rs`,
`rtc-shared/src/tcp_framing.rs`, `src/peer_connection/handler/ice.rs`,
`src/peer_connection/transport/ice/`. All sections (3 to 12) are done.

Level `MUST*` marks a requirement stated without an RFC 2119 keyword; it is counted as MUST.

The engine is sans-I/O: the application owns every TCP socket. It makes the candidates
(`add_local_candidate`), opens, accepts and closes connections, and applies RFC 4571 framing
with `rtc_shared::tcp_framing`. The engine sees one datagram per frame, tagged
`TransportProtocol::TCP` with the connection's addresses. Clauses about connection lifetime are
therefore `n/a` (application's job) unless the engine has to do something for them to be
possible, and a "tested" framing verdict means the helper and the integration tests that use it.

## Gaps, in order of importance

1. **Reconnecting a selected TCP pair** (11.1-3 missing, 11.1-6 partial, 11.1-4 and 9.2-1
   untested). Size M. Options: treat an authenticated check from the same remote IP on the
   selected pair's passive local candidate as that pair's new connection (move the selected
   pair's remote port), or let the controlling side re-nominate the new pair. Add a
   `tests/ice_tcp_rtc2rtc.rs` case that drops the simulated connection after selection.
2. **`tcptype` on non-host candidates** (4.5-1 partial; RFC 8839 5.1-11). Size S. Give the
   srflx / prflx / relay configs a `tcp_type`, keep it in `RTCIceCandidate::to_ice`, write
   `tcptype` after `raddr` / `rport`, parse it wherever it stands among the extensions, and fail
   (or ignore) a TCP candidate without it.
3. **Unique other-pref** (4.2-7 violated; 4.2-3 partial). Size S. Derive other-pref from the
   local address's rank (the agent knows every local candidate), and lower TCP type preferences
   so UDP is preferred for media (libwebrtc uses 90 for TCP host).
4. **Connection events from the application** (7.1-4 partial, 7.1-6 missing, 12-1 missing).
   Size M. An agent call such as `tcp_connection_failed(local, remote)` that fails the pair at
   once; fail every pair of a remote candidate whose first reply is not STUN; cap pending
   active-pair checks per remote IP at 5.
5. **No per-transaction pacing or priority order, repeated requests over TCP** (4.1-9, 7-1, 7.1-5
   partial). Size L, shared with RFC 8445 (Ta, checklist order); for TCP, send one request per
   pair and wait for the reply instead of repeating it each interval.
6. **Port 9 for active candidates** (4.5-2 partial). Size S. Write port 9 for an active local
   candidate whatever the application gave; fix `test_candidate_marshal`'s port 0 case.
7. **Relayed TCP candidates** (4.1-5, 5-1, 5.5-1 missing; 4.5-3 n/a until then). Size L:
   RFC 6062 in `rtc-turn` (its own audit) plus relayed TCP candidates here.
8. **Lite with TCP and two lite agents** (6.1-1, 6.1-3 missing; 4.4-1 untested). Size M; a lite
   agent should also refuse active TCP candidates.
9. **Simultaneous-open and connection reuse over a restart** (9.2-2 missing; 6.2-1 S-O arm
   untested). Size M.
10. **NAT-assisted and UDP-tunnelled candidates** (5.3-1, 5.4-1 MAY, missing). Size S if they are
    only new type preferences (105, 75) for application-made candidates.
11. **Tests**: SRTP media over a TCP pair (4.5-7), TCP over IPv6 (5-2), reflexive direction-prefs
    (4.2-6). Size S.
