# RFC 7350 conformance audit: DTLS as a transport for STUN and TURN (client side)

Spec: RFC 7350, "Datagram Transport Layer Security (DTLS) as Transport for Session Traversal
Utilities for NAT (STUN)", August 2014 (current). It also fixes the `turns:` URI rules for
TLS and DTLS that RFC 8656 and RFC 7065 rely on.

Audited on branch `conf/tcp-3-turn-tls`. Code: `src/peer_connection/turn_streams.rs`
(`EngineTurn::new`), `src/peer_connection/turn_tls.rs`, `rtc-ice/src/url/mod.rs`. Server and
STUN-usage-writer clauses are grouped as `n/a`.

Result in one line: **TURN over DTLS is implemented** (branch `conf/tcp-12-turn-dtls`): a
`turns:...?transport=udp` server is reached with a client-role `rtc-dtls` association from a
UDP host candidate's base, on the application's socket, its datagrams taken out of
`handle_read` before ICE (`take_turn_dtls`); the certificate is checked like TLS's, the TURN
client runs over it with UDP's retransmissions and the relayed candidate's `relayProtocol` is
`dtls`. STUN over DTLS (server-reflexive gathering from `stuns:` over UDP) is not run.
