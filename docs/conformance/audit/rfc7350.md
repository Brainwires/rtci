# RFC 7350 conformance audit: DTLS as a transport for STUN and TURN (client side)

Spec: RFC 7350, "Datagram Transport Layer Security (DTLS) as Transport for Session Traversal
Utilities for NAT (STUN)", August 2014 (current). It also fixes the `turns:` URI rules for
TLS and DTLS that RFC 8656 and RFC 7065 rely on.

Audited on branch `conf/tcp-3-turn-tls`. Code: `src/peer_connection/turn_streams.rs`
(`EngineTurn::new`), `src/peer_connection/turn_tls.rs`, `rtc-ice/src/url/mod.rs`. Server and
STUN-usage-writer clauses are grouped as `n/a`.

Result in one line: **TURN over DTLS is not implemented.** The engine runs `turns:` servers
over TLS on TCP (RFC 8656 section 3.1) and leaves a `turns:...?transport=udp` (DTLS) server
alone, as section 4.2's resolution rule demands of a client without DTLS. Running it needs a
second, client-role `rtc-dtls` endpoint on the application's UDP socket (the engine would
demultiplex the server's datagrams before ICE); size M, not started.
