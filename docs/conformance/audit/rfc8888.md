# RFC 8888: RTP Control Protocol (RTCP) Feedback for Congestion Control

Spec: RFC 8888, January 2021 (Proposed Standard). Audited against fork master 8916bc3.
Sections done: 3, 3.1, 4, 5, 6, 7 (all normative text). Sections 1, 2, 8, 9, 10, 11 carry no clause that binds an endpoint.

Scope of the code: wire codec `rtc-rtcp/src/transport_feedbacks/cc_feedback_report/mod.rs`; receiver side
`rtc-interceptor/src/rfc8888/{sender,recorder,stream_log}.rs`; sender side `rtc-interceptor/src/rtpfb/{convert,history}.rs`,
`rtc-interceptor/src/cc/interceptor.rs`, `rtc-interceptor/src/gcc/estimator.rs`; SDP `src/peer_connection/sdp/mod.rs`,
`rtc-sdp/src/util/mod.rs`; helpers `src/peer_connection/configuration/interceptor_registry.rs`.

**Since the audit** (the table and the totals are current; the gap and bug lists below are the audit's):
bugs B2, B3, B4, B6 and B7 are fixed, each first reproduced by a failing test
(`a_stream_that_did_not_negotiate_ccfb_gets_no_report`,
`a_receive_only_endpoint_reports_from_a_non_zero_ssrc_of_its_own`,
`a_duplicate_reports_the_first_arrival_and_ce_if_any_copy_was_marked`,
`one_lost_packet_does_not_make_every_report_repeat_the_window`,
`the_over_range_offset_yields_no_arrival_time`), and one the audit did not list: the sender side
handed the arrival time *offset* to the estimator as the arrival time, so arrivals ran backwards
within every report (`ccfb_arrival_times_increase_with_arrival_order`). B1 is in `rtc-sdp`, B5 in
`src/peer_connection/handler`.

Totals (MUST includes MUST NOT/SHALL; SHOULD includes SHOULD NOT/RECOMMENDED):

- MUST: tested 17 / untested 3 / partial 1 / missing 5 / violated 1 / n-a 1
- SHOULD: tested 1 / untested 1 / partial 2 / missing 3 / violated 0 / n-a 1
- MAY: tested 3 / untested 0 / partial 1 / missing 1 / violated 0 / n-a 0

## Gaps, in order of importance

1. **SDP form of ccfb (M).** RFC8888-6-1. Emit `a=rtcp-fb:* ack ccfb`, parse the wildcard payload type in `rtc-sdp`
   (`parse_rtcp_fb` needs a wildcard codec entry that `codecs()` applies to every format), keep accepting the per-PT
   form. Without it the feature interoperates only with itself.
2. **Send CCFB only when negotiated, from a real SSRC (S).** RFC8888-6-3, RFC8888-3.1-3. Gate `bind_remote_stream` on
   `ack ccfb` in `info.rtcp_feedback`; pass the connection's RTCP SSRC to `Rfc8888Builder::with_sender_ssrc`.
3. **Duplicates (S).** RFC8888-3.1-20, -21. Keep the first arrival in `StreamLog::add`, upgrade the mark to CE if any
   copy is CE.
4. **RTX and FEC flows in the feedback (M).** RFC8888-6-2, RFC8888-3.1-15. Record a repair packet under its own SSRC
   and sequence number before it is de-encapsulated; on the send side record RTX/FEC departures in `History` under the
   repair SSRC (today `cc/interceptor.rs:204` only knows `info.ssrc`).
5. **Response to missing feedback (M).** RFC8888-5-1, -5-2 (also RFC 8836 req. 10, RFC 8083). Give `Gcc` a
   `handle_timeout`/`poll_timeout` that halves the target after N missed intervals.
6. **ECN per RFC 6679 (L).** RFC8888-7-1, -7-4, -7-5, -7-6. `a=ecn-capable-rtp`, the initiation probe, CE as a
   congestion signal in the estimator, and stopping ECT on failure.
7. **One feedback mechanism per answer (S).** RFC8888-6-4, -6-5.
8. **Splitting oversized reports, 0x1FFE on the sender side (S).** RFC8888-3.1-18, -3.1-13.
9. **Tests (S).** RFC8888-3.1-14 (RTS against the SR NTP clock), -3.1-23, -6-6.

## Bugs found

- **B1. A wildcard `a=rtcp-fb:* ...` line is silently dropped.** `rtc-sdp/src/util/mod.rs:194`
  (`pt_split[1].parse::<u8>()?`), swallowed at `rtc-sdp/src/description/media.rs:111-115`. Reproduce: parse a media
  section with `a=rtcp-fb:* ack ccfb` (or `* nack`), call `MediaDescription::codecs()`, expect the feedback on every
  codec; it is on none. Also affects RFC 4585 wildcard feedback generally.
- **B2. CCFB is sent for streams that did not negotiate it.** `rtc-interceptor/src/rfc8888/sender.rs:226`. Reproduce:
  bind a remote `StreamInfo` with empty `rtcp_feedback`, feed RTP, advance 100 ms: a `CcFeedbackReport` is written.
- **B3. Reports claim sender SSRC 0.** `interceptor_registry.rs:709`, `:842`. Reproduce: build a peer connection with
  `configure_congestion_control_feedback`, capture the first CCFB: `sender_ssrc == 0`.
- **B4. A duplicate overwrites the first copy's arrival time and ECN mark.** `rfc8888/stream_log.rs:68`. Reproduce:
  `log.add(t0, 100, Ecn::Ce); log.add(t0 + 50 ms, 100, Ecn::Ect1); metrics_after(t0 + 60 ms)`: the block says ECT(1)
  with a 10 ms offset; the RFC wants CE with 60 ms.
- **B5. A retransmission is reported as the original packet arriving late.** `handler/interceptor.rs:1011` runs
  before `Rfc8888Interceptor::handle_read`. Reproduce in a peer-connection test: drop original seq 10, deliver its RTX
  copy 80 ms later; the next CCFB reports (primary SSRC, seq 10) received with the RTX arrival time and no block for
  the RTX SSRC. On an engine sender this lands in `History::on_ccfb_feedback` as an 80 ms delay spike.
- **B6. After one unrecovered loss every report repeats the whole window.** `rfc8888/stream_log.rs:112-140`:
  `next_to_report` stays at the gap until the byte budget pushes it out (about 590 packets at 1200 bytes), so each
  100 ms report re-describes everything since the loss, with offsets saturating at 0x1FFE. Not a violation; a large
  overhead. Reproduce: lose one packet, deliver 500 more, count metric blocks per report. Fix idea: give up a gap after
  a reordering window, as the TWCC recorder does (500 ms).
- **B7. The sender treats 0x1FFE as a measured arrival.** `rtpfb/convert.rs:147`. Reproduce: a block with
  `arrival_time_offset: 0x1FFE` converts to `arrival: Some(7.998 s)`.

## Status after `conf/rtcp-codec` (rtc-rtcp)

No verdict changes: the codec rows were already tested and the open rows are SDP and the interceptors. The
codec now cuts RTCP padding before it reads the report timestamp (a padded CCFB used to take its timestamp
from the padding).
