# RFC 7675: STUN Usage for Consent Freshness, clause audit

Spec: RFC 7675, October 2015. Audited against fork master 8916bc3.
Code: `rtc-ice/src/agent/mod.rs` (`validate_selected_pair`, `check_keepalive`,
`handle_inbound`), `rtc-ice/src/agent/agent_selector.rs`, `src/peer_connection/handler/ice.rs`.

Totals (19 rows; `MUST (proc)` rows are behaviour the RFC states without a keyword and count
as MUST):

- MUST: tested 10 / untested 2 / partial 1 / missing 0 / violated 0 / n-a 0
- SHOULD: tested 2 / untested 0 / partial 0 / missing 0 / violated 0 / n-a 2
- MAY: tested 0 / untested 0 / partial 0 / missing 1 / violated 0 / n-a 1

How it works here: the keepalive of RFC 8445 §11 is a Binding request on the selected pair
every `keepalive_interval`. A success response to one of those requests, authenticated and
matched by transaction id and destination, sets `Candidate::last_consent`. With no such
response for `disconnected_timeout` (5 s) the agent is `Disconnected`, and after
`disconnected_timeout + failed_timeout` (5 + 25 = 30 s) it is `Failed`, which drops the
selected pair and with it the media path. Tests are in `rtc-ice/src/agent/` unless a path is
given.

## Gaps, in order of importance

1. **WP-CONSENT-1: the consent timer (S).** Default period 5 s, each interval drawn from
   0.8 to 1.2 of it with the crypto provider's RNG, a floor of 4 s on the configured value
   (5.1-3, 5.1-4, 5.1-5). Fix the `keepalive_interval` doc comment. Needs `poll_timeout` to
   return the jittered deadline rather than a fixed tick. Tests: interval bounds over many
   draws, a configured 1 s is raised or refused, two consecutive requests differ in
   transaction id (5.1-6).
2. **WP-CONSENT-2: consent during an ICE restart (M).** Keep the old pair, its remote
   candidate and the old credentials alive beside the new generation, keep sending consent
   requests on it and drop `previous_media_path` when 30 s pass without a response (5.1-11,
   5.1-2). Today a restart is the one time data flows unchecked.
3. **WP-CONSENT-3: the 30 s bound (S).** Consent expiry is `disconnected_timeout +
   failed_timeout`, which the application can stretch or switch off. Either cap the sum at
   30 s for the purpose of stopping transmission or separate "consent expired" from the
   W3C `failed` timer (5.1-2). Clear `pending_binding_requests` on expiry (5.1-9). Refuse
   reuse of the lost session's credentials (5.1-15).
4. **WP-CONSENT-4: response wait from RTT (S).** Replace the fixed 4 s with a bound derived
   from the pair's measured RTT (5.1-7). Belongs with the STUN transaction work of
   `rfc8445.md` WP-ICE-1.
5. **WP-CONSENT-5: tests (S).** Consent expiry on a TCP pair (5.1-12); no data leaves after
   `Failed` at the peer-connection level.

## Bugs found

Fixed on `conf/ice-2-consent`, each with the test named in its row: 1, 2, 3. (The totals line
above counted one "partial" MUST that the table has as "tested"; it is recounted from the
rows.)

What "Disconnected" means changed with the interval: consent requests are now 4 to 6 seconds
apart, so "no response for `disconnected_timeout` (5 s)" would be true between two answered
requests. The agent is Disconnected when a consent request has been unanswered for
`disconnected_timeout`, which is 9 to 11 seconds after the last response by default (it was 5).

1. **Consent checks are sent every 2 s, with no jitter** (`rtc-ice/src/agent/agent_config.rs:15`,
   `rtc-ice/src/agent/mod.rs:1285`). The RFC forbids a period under 4 s and requires
   randomization. Reproduce: connected pair, default configuration, advance virtual time by
   60 s and count Binding requests on the selected pair: 30, evenly spaced; expected 10 to 15
   with intervals spread over 4 to 6 s.
2. **Data flows without consent during an ICE restart**
   (`rtc-ice/src/agent/mod.rs:973-997`). Reproduce: connect two agents, `apply_restart` on
   one and never give it remote credentials (the peer has gone away); with `failed_timeout`
   0 `media_path()` stays `Some` for ever, and with defaults it stays for the whole checking
   timeout although no response has arrived on that path since the restart. Expected: the
   path ends 30 s after the last consent response.
3. **`AgentConfig::keepalive_interval` is documented as defaulting to 10 seconds**
   (`rtc-ice/src/agent/agent_config.rs:123-126`); the constant is 2 s.
