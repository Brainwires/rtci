# RFC 8260: Stream Schedulers and User Message Interleaving for SCTP

Spec: RFC 8260, November 2017 (Proposed Standard). Audited against fork master 8916bc3 (`docs/conformance-audit` worktree), read-only.

RFC 8260, Stream Schedulers and User Message Interleaving for SCTP, November 2017. Two parts. User
message interleaving (I-DATA, I-FORWARD-TSN; section 2) is not implemented and is on the "Not
implemented, on purpose" list of `docs/conformance.md`; every clause is listed and counted `missing`.
Of the stream schedulers (section 3) the engine has first-come-first-served (with a twist) and Weighted
Fair Queueing at message granularity; the other four are absent. Because I-DATA is never advertised,
no association can negotiate it, so the missing clauses cannot be reached by a conformant peer; what
a non-conformant peer sees is in Bugs.

Totals (52 clauses):

- `MUST: tested 5 / untested 2 / partial 0 / missing 33 / violated 0 / n-a 0`
- `SHOULD: tested 1 / untested 0 / partial 0 / missing 1 / violated 0 / n-a 0`
- `MAY: tested 0 / untested 0 / partial 1 / missing 8 / violated 0 / n-a 1`

Levels: MUST covers MUST / MUST NOT / SHALL / REQUIRED and procedure steps the RFC words in
lower case ("must", field definitions); SHOULD covers SHOULD / SHOULD NOT / RECOMMENDED; MAY covers
MAY / OPTIONAL, each counted as a feature. Code paths are relative to `rtc-sctp/src/`; tests are
function names in that crate. `untested` with the note "by construction" means the code cannot do
otherwise but nothing would fail if it started to.

## Gaps, in order of importance

1. **I-DATA and I-FORWARD-TSN (XL).** New chunk types 64 and 194 with parsers and fuzz targets;
   negotiation through Supported Extensions with an application opt-in; per-stream ordered and
   unordered MID counters; a reassembly queue keyed on (SID, U, MID, FSN); ABORT on the wrong chunk
   family; MID reset on stream reset; I-FORWARD-TSN in the abandonment path of `rfc3758.md`. Closes
   RFC8260-2-1, 2-2, 2.1-1..11, 2.2.1-1, 2.2.1-2, 2.2.2-1..7, 2.2.3-1..4, 2.3.1-1..6, 2.3.1-8,
   2.3.1-10, 2.3.2-1. Sub-packages: wire formats (M), receiver (L), sender with per-stream message
   state (L), PR-SCTP and reset interaction (M).
2. **Interleaving WFQ (M, after 1).** Schedule per chunk instead of per message once I-DATA is
   negotiated. Closes 2.2.2-6, 3.6-3.
3. **ABORT on an un-negotiated I-DATA / I-FORWARD-TSN (S, independent of 1).** Recognise types 64 and
   194 enough to answer with ABORT, Protocol Violation. Closes 2.2.3-5, 2.3.1-11. (General handling of
   unknown chunk types by their upper two bits belongs to the RFC 9260 audit.)
4. **True first-come-first-served (S).** One queue in arrival order, or document the unordered-first
   rule as a seventh, non-RFC scheduler. Closes 3.1-1.
5. **Remaining schedulers (M, optional).** Round-robin, round-robin per packet, strict priority, fair
   capacity on the `PendingQueue` scheduler seam. Closes 3.2-1, 3.3-1, 3.4-1, 3.5-1.
6. **Tests (S).** Assert the Supported Extensions list an INIT / INIT ACK carries (2.2.1-4, 2.3.1-9).

## Bugs found

1. **A packet containing an I-DATA or I-FORWARD-TSN chunk is dropped whole and unanswered**
   (`packet.rs:155` / `:252` return `ErrUnmarshalUnknownChunkType`; `association/mod.rs:624-629` logs
   and returns). RFC 8260 2.2.3 / 2.3.1 require an ABORT. A peer that wrongly sends I-DATA sees a
   black hole and retransmits until its own limit. Reproduce: after the handshake deliver a packet
   whose only chunk has type 64 and a valid 20-byte header; assert an ABORT with Protocol Violation
   leaves `poll_transmit` and the association ends.
2. **With the default scheduler a steady flow of unordered messages starves every ordered message,
   DCEP included** (`queue/pending_queue.rs:390-402`: the unordered queue always goes first; reset
   markers wait behind it too, `:435-437`). Reproduce: keep one unordered stream's queue non-empty
   under a small cwnd, write one ordered message and close another stream; neither the ordered
   message nor the RE-CONFIG leaves until the unordered queue is empty.
