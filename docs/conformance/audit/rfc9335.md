# RFC 9335 — Completely Encrypting RTP Header Extensions and CSRCs (Cryptex): clause audit

Spec: RFC 9335, January 2023 (current; updates RFC 3711). Audited against fork master 8916bc3; verdicts updated for branch `conf/srtp-conformance`.
Scope: `rtci-srtp/src/cryptex.rs`, the `*_cryptex` methods of both ciphers, `rtci-srtp/src/context/srtp.rs`,
`src/peer_connection/cryptex.rs`, `src/peer_connection/handler/srtp.rs`, the call sites in
`src/peer_connection/mod.rs`. Read-only audit; no test was run. SHALL / REQUIRED count as MUST;

## Open after `conf/srtp-conformance`

1. **End-to-end test that negotiation reaches the wire (S, peer connection)**: 4-3, 4-5, 4-6.
2. **Reading the violation event (S, peer connection)**: `ContextEvent::CryptexRequiredViolation` is
   raised by the receiving context (5.2-3); `src/peer_connection/handler/srtp.rs` does not poll it.
3. **Per-packet / per-sender choice (S, optional)**: 4-2.
4. **Default policy (S, decision)** and **TRANSPORT mux category (S)**: 9.1-1, W3C-1, unchanged.
5. **appbits (S)**: 5-2 stays "untested" for its SDP half.

  with Cryptex when it is required;
  `cryptex_test.rs::cryptex_required_never_sends_csrcs_or_extensions_in_the_clear`.
