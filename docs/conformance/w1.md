### Decisions

| Clause | What the engine does |
|---|---|
| RFC 8841 9.3, closing an association that signalling replaces or closes | An ABORT, not the SHUTDOWN handshake: the new association does not wait for the old one, and messages still queued on the old one are dropped with it. |
| RFC 8841 10.5, a DTLS association replaced under a live SCTP association | The SCTP association is kept: a DTLS handshake that completes again starts no new one. |
| Pre-RFC data sections (`m=application <port> DTLS/SCTP <sctp-port>` with `a=sctpmap`) | Not supported: rejected with the offer's own m= line. No current browser sends them. |
| RFC 8831 6.6, deprecated PPID-based fragmentation (PPIDs 52 and 54) | Not reassembled: such a message closes the channel, as any unsupported PPID does. |
| RFC 8832 7, a bound on channels the peer opens | None below the negotiated stream count: each channel costs a registry entry and its statistics, freed when it closes. |

### Open in this area

| Clause | State |
|---|---|
| RFC 8831 6.4, weighted fair queueing by default | The priority is applied, but the scheduler is opt-in (`SettingEngineBuilder::with_sctp_weighted_fair_queueing`); without I-DATA it schedules whole messages. |
| RFC 8831 6.1 and 6.6, message interleaving and the 16 KB rule without it; RFC 8831 5 and RFC 8261 4 and 6, path MTU discovery and the path-change reset | Need I-DATA (RFC 8260), PAD and probing (RFC 4820, RFC 8899) and a path-change entry in `rtc-sctp`. |
| RFC 8841 9.3, INIT collision routing | The peer's INIT reaches the association this side initiated through `init_for_existing_association` in the handler, until `rtc-sctp`'s `Endpoint::handle` routes it itself. |
| RFC 8841 10.1 `a=tls-id`; 10.5 closing SCTP and DTLS together by rejecting the data section in an offer; 12.2 proto derived from the default candidate | Not implemented. |
